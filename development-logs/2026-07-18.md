## Phase 3 Task 4: bounded deterministic document parsing

- Added an offline parser adapter for PDF, DOCX, Markdown, TXT, HTML, CSV, and XLSX. Parsed
  content now retains immutable source-addressable elements, headings, page numbers, table rows,
  and worksheet locations alongside flattened deterministic text.
- Each parse uses a fresh Windows-compatible `spawn` child and a one-way `Pipe`; the parent owns
  the deadline, terminates then kills a timed-out child if needed, joins it, and only reconstructs
  domain objects from plain DTO data. Parser modules receive bytes only and never open a supplied
  path or make a network request.
- PDF pages with no extractable text return `ParsingStatus.OCR_REQUIRED` and an explicit
  `OCR_REQUIRED` body rather than silently treating a scanned document as empty.
- Parser budgets cover input bytes, characters, pages, rows, cells, office members, expansion,
  compression ratio, and elapsed time. DOCX/XLSX repeat container checks defensively; XLSX opens
  with `read_only=True`, `data_only=True`, and `keep_links=False`, so formulas, VBA, and links are
  not executed or followed. HTML uses static BeautifulSoup extraction after removing active tags.
- Pinned compatible dependencies: pypdf 6.14.x (BSD-3-Clause, offline PDF text); python-docx
  1.2.x (MIT, DOCX structure); openpyxl 3.1.x (MIT, read-only spreadsheet values); BeautifulSoup
  4.15.x (MIT, static HTML); defusedxml 0.7.x (PSF-2.0, bounded OOXML manifest parsing). These are
  parser-only libraries; no cloud SDK or executable-document capability was introduced.
- TDD: RED was one missing-module collection error. GREEN was `10 passed` for the Task 4 suite;
  related RAG parsing/intake/ports coverage was `48 passed`; `ruff check backend` passed.
