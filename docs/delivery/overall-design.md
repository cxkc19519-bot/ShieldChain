# ShieldChain 总体设计说明

> 文档状态：当前参考（更新于 2026-08-08）。

ShieldChain 采用前后端分离、服务端安全边界和可替换模型后端。React 前端负责运营交互；FastAPI 负责权限、持久化、RAG、智能体、工具、审计和报告；Wazuh/OpenSearch 提供真实安全遥测；Milvus 和本地模型服务可独立部署。

部署 readiness（就绪度）检查会把外部依赖、模型可用性和真实设备路径标为已验证或未验证，避免把演示环境状态误报为生产能力。

## 核心组件

- **前端**：运营总览、安全运营报告、实时告警、知识库、历史报告和智能助手。
- **API**：稳定的公开视图，返回结构化可审计推理链和证据域状态，但不返回私有上下文、隐藏思维链和原始敏感载荷。
- **智能体运行时**：七个角色、ReAct 选择、预算、循环检测、交接和安全降级。
- **运营报告服务**：时间参数、四类只读 MCP、跨域证据覆盖、结构化推理链、闭环状态、综合分析、格式转换和预览。
- **RAG**：持久化文档、LLM/规则分块、BM25、BGE-M3、Milvus 和 Reranker。
- **数据接入**：Wazuh 告警收件箱与离线 NTA 数据集。
- **可信工具网关**：与只读 MCP 分离，承载需要审批的真实变更动作。

## 设计原则

- 真实数据与演示数据必须明确标识；
- 模型自主性受工具注册、模式校验、预算和策略约束；
- 分析结果不等于处置授权；
- 失败安全关闭并保留可审计原因；
- 数据和模型供应商可替换；
- 本地持久化数据不会因应用重启丢失。
