# ShieldChain 项目总结

> 文档状态：当前参考（更新于 2026-09-07）。

ShieldChain 已从固定安全仿真演示演进为真实安全数据驱动的多智能体分析系统。项目能够接入 Wazuh 告警、漏洞扫描结果和离线 NTA 数据，使用七个通用专业角色进行 ReAct 协作，并通过知识库、历史报告和四类只读 MCP 生成可追溯的安全运营报告；专用漏洞分诊智能体负责漏洞优先级与修复、复测建议。

## 已实现

- Wazuh 高风险告警接收、去重、持久化和前端展示；
- 告警分诊智能体公开证据、人工误报/有效/证据不足定性、追加式审计、限时抑制建议和案件级误报统计；抑制建议不自动修改 Wazuh；
- 漏洞扫描结果可通过独立扫描器令牌幂等接入；专用智能体结合本地 RAG 和模型输出结构化分诊，人工完成修复批准、风险接受或不受影响判断，并以变更单、实施回执和复测结果形成审计闭环；
- 总控、分诊、研判、检索、响应规划、验证和报告七个专业角色；
- 模型自主选择角色和只读工具的 ReAct 运行；除总控外的六个专业执行角色均可按职责自主调用本地 RAG，每个角色保留独立查询与观察记录；
- 事件、告警、漏洞、弱密码四类 MCP；
- 运营响应规划角色生成严格零动作建议，服务端完成证据/目标/工具重绑定和版本化计划审计；
- 案件级计划支持接受/拒绝，并逐动作映射到现有可信工具策略、审批、幂等和依赖验证边界；
- 离线仿真 Adapter 已形成耐久租约、执行/验证 deadline、ReAct 观察、状态查询、失败 revision、人工接管、周期恢复和按成功尝试重建状态的重启闭环；
- MCP Server、批准目录、外部 peer、Agent Tool/MCP 调用、响应计划、可信调用和 ReAct 轨迹均提供租户化安全公开投影；
- 处置中心逐动作区分建议、计划接受、工具审批、执行和验证；智能体页展示目录 revision 与裁剪回执，运营报告链接实时闭环状态；
- 安全运营报告 Markdown、HTML、下载与预览；
- 本地知识库、LLM 语义分块、规则降级、混合检索和 Reranker；
- 多智能体 RAG 明确区分“知识依据”和“当前事件事实”；空库、无命中或检索故障均安全降级，不会扩写为已确认事实；
- 智能助手对话、摘要记忆和历史报告检索；
- Windows 一键启动、Docker 服务器部署和本地 vLLM 覆盖配置；
- 中文公开审计、轨迹和失败状态。
- 官方 MCP SDK conformance、迁移往返、后端完整回归 `1259 passed, 33 skipped`、前端完整回归 `124 passed`、静态容器安全合同和零漏洞前端依赖审计门禁；漏洞闭环后续安全契约变更另有 5 条受影响回归通过；

## 当前边界

- 运营报告已关联严格计划，但报告级运行没有单一案件目标，只生成零动作建议，不自动执行真实处置；
- 本地 30B 模型服务启动依赖完整权重和两张可用 RTX 4090；
- SQLite 适合单实例演示，不代表生产高可用；
- 闭环 Adapter 已在服务器实验室接入测试地址 nftables、演示 Agent `002` 网络隔离和独立卷限定文件隔离，并完成审批、执行、验证和恢复；这些仍不是生产防火墙、EDR 或账号系统，真实生产网络、设备、遥测回流和大规模并发仍需授权环境验收；
- 共享服务器资源需要人工协调。
- 当前没有真实管理员 RBAC；因此生产环境 REST 只读，计划、工具、急停和 ReAct 写控制明确返回拒绝；
- 漏洞修复批准、风险接受、变更登记、实施回执和复测属于人工写操作；生产模式默认拒绝这些 REST 写请求，只有显式启用操作员控制后才可用于受控演示，真实环境仍需接入 SSO/RBAC；扫描器接入始终要求独立令牌；
- 前端已完成兼容补丁升级，当前 `npm audit --audit-level=moderate` 为 0 漏洞；
- 当前主机没有 Docker CLI，Windows PowerShell 也没有 `npm.cmd`；容器 runtime 与单命令 Windows 综合 verify 尚未形成实际通过证据；

## 已删除

- 固定钓鱼模拟攻击功能和对应产品入口；
- Remotion 视频工程、比赛 MP4 和相关测试；
- 把固定顺序工作流宣传为自主智能体的表述。

## 下一步

1. 在具备 Docker CLI/daemon 的环境完成容器 runtime、升级和回滚演练；
2. 完成本地 Qwen3-30B-A3B 权重下载、vLLM 启动和工具调用验收；
3. 在生产授权条件下评估 Wazuh 告警的策略触发调查；当前仍由操作员显式启动，避免告警接收直接触发模型或处置；
4. 将已实现的通用漏洞扫描接入契约对接实际扫描器（如 OpenVAS/Greenbone），并补充弱密码真实数据适配器；
5. 完成真实身份/RBAC、TLS、备份恢复和生产数据库迁移；
6. 将已验收的实验室 Adapter 接入获授权的生产靶场，并补齐真实身份、双人审批、失联恢复和端到端人工处置演练。
