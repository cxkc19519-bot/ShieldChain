# 安全知识库、RAG 与智能助手实施方案

> 文档状态：功能实现完成、完整模型复验待具备运行条件（2026-09-04）。工作分支：`codex/security-knowledge-rag-assistant`。

## 1. 当前基线审计

项目已经具备知识库持久化、版本/分块管理、BM25 与向量混合检索、重排、引用、证据不足拒答，以及使用知识库和历史报告的多轮智能助手。当前主要缺口不是“从零搭框架”，而是把领域知识变成可审计资产、把 RAG 效果变成可重复指标，并让助手对过期、冲突和无依据内容稳定拒答。

原根目录三份旧样例存在无法充分核验或可能误导的内容，已改为退役提示；现行材料只从 `sample_docs/security_vertical/manifest.json` 进入受管导入流程。

## 2. 分阶段交付

### 阶段一：可验证的安全垂直知识包（已完成）

- 覆盖行业监管政策、0day/在野利用漏洞响应、MITRE ATT&CK 技战术图谱、维护规范和深信服官方安全研究基线；
- 一级权威事实源使用中央网信办、CISA、MITRE 官方站点与 MITRE 官方 GitHub 数据仓库；深信服千里目、PSIRT、规则库和正式研究报告作为官方厂商研究源，不替代其引用的第三方原始来源；
- 深信服 2025 年漏洞趋势、APT 趋势、年度安全趋势和 2026 年 3 月上期半月刊的官方 PDF 已归档到 `sample_docs/security_vertical/`，清单校验后由 RAG 直接解析，不要求 Agent 运行时联网读取网页；
- 中央网信办《网络数据安全管理条例》《国家网络安全事件报告管理办法》《金融信息服务数据分类分级指南》答记者问的官方 HTML 原文，以及行政法规目录的访问日快照，已归档并由 RAG 本地解析；目录快照只用于发现更新，不替代具体法规正文；
- 清单记录包版本、核验/复核日期、使用政策，以及每份文档的类别、SHA-256、权限标签、复核角色和来源元数据；
- 导入前封闭校验 schema、路径、符号链接、哈希、UTF-8、标题、来源域名、正文引用和复核期限；
- 任一校验失败则整包拒绝，避免半包入库；重复导入跳过现有同名文档；
- 提供服务端导入 API 和知识库页面入口，并返回版本、核验日期、复核期限、使用政策和导入结果；
- Docker 镜像包含该知识包，路径可通过 `SECURITY_VERTICAL_PACK_ROOT` 配置。

当前边界：内容由项目组依据权威来源整理，不等于法律意见、漏洞情报订阅或 MITRE 原始数据镜像；仍需团队安排领域专家签字和定期更新责任人。

### 阶段二：RAG 固定数据集与量化门禁（代码与降级验收已完成）

1. **已完成**：建立版本化固定问答集，当前 12 条用例覆盖监管条款、漏洞响应、ATT&CK 映射、深信服研究、跨语言检索和无依据拒答；过期来源和显式冲突另有服务级回归测试。
2. **已完成**：修复本地评测服务的接口合同，API 对用户所选知识库真实执行数据集，不再返回空指标；未知数据集、缺失知识库范围和非法路径失败关闭。
3. **已完成当前检索链路**：已计算 Recall@5、MRR/nDCG、BM25 基线、重排增益、引用正确率、引用精确率、期望引用召回率、抽取式忠实度、拒答准确率、延迟、调用次数与失败率；完整 Qwen 生成链路仍需另加语义声明级忠实度。
4. **已完成**：固定知识包版本、查询、期望文档/块和阈值；API 与页面提供逐题命中、引用、拒答、分数和失败原因；结果保存为可复查报告，禁止用训练/调参集冒充留出集。
5. **已完成可运行入口**：`scripts/run_rag_evaluation.py` 可在隔离临时目录导入同一知识包并输出完整 JSON。分别记录纯 BM25、本地向量/重排和完整 Qwen 链路；模型不可用时如实标记降级，不用替代结果冒充完整链路通过。

2026-09-03 已保存首份真实降级基线：Recall@5 0.70、MRR@5 0.6333、nDCG@5 0.6103、引用正确率 0.2667、引用精确率 0.3667、期望引用召回率 0.80、抽取式忠实度 1.0、拒答准确率 1.0；因 BGE/Milvus/Reranker 未启动且关键指标低于门槛，质量门禁按设计失败。详见 `docs/reports/rag-security-vertical-baseline-2026-09-03.md`。

2026-09-04 加入确定性中文二/三元词组后复跑 BM25 降级基线：Recall@5 提升至 0.85、期望引用召回率提升至 0.90，但 MRR、nDCG、引用精确率和依赖失败率仍未过门禁。结果保存在 `docs/reports/rag-security-vertical-bm25-2026-09-04.md`；这证明降级检索改善，不代表 BGE/Milvus/Reranker 已验收。

完成标准：同一数据集可在本地重复运行；每项指标有明确分母、阈值和失败原因；空数据集不得通过质量门禁。

### 阶段三：有依据的智能助手（已完成当前交付范围）

1. **已完成**：知识包导入时将官方来源等级/URL、核验日期和文档复核截止日期持久化；助手页面展示文档、版本、内容块、标题路径、页码/结构位置、融合分数、SHA-256 与上述来源元数据。
2. **已完成**：助手响应和持久化消息区分 `grounded`、`extractive_degraded`、`refused`、`conversational`，并保留检索降级与拒答原因；底层服务排除超过复核期限的受管资料，显式证据声明同时存在支持/反对标记时返回 `conflicting_evidence`。
3. **已完成当前固定门禁**：已有本地多轮记忆、历史报告同步、证据不足拒答、寒暄绕开 RAG、生成失败抽取降级、提示注入拒答和引用持久化测试；`shieldchain-assistant-v1` 固定集覆盖中英文寒暄、法规、0day、ATT&CK、深信服报告、无依据和提示注入。
4. **已完成当前边界**：普通对话明确标记为未检索知识库，安全知识回答只把本地 RAG 片段交给生成模型；当前助手没有把联网摘要写成已入库事实。
5. **已完成当前边界**：只保存公开答案、依据状态、拒答/降级原因和证据定位，不保存隐藏思维链、系统提示词、凭据或原始工具载荷。

生成模型不可用时，助手不再返回 503 并丢弃已检索证据，而是返回最多 3 条可逐字核验的片段，标记 `generation_degraded` 并提示人工复核。生成提示词中原先“正文输出引用编号”和“禁止引用编号”的冲突要求已统一：正文保持纯文本，来源由界面独立、可展开地展示。

2026-09-04 使用 13 份受管资料运行离线抽取式助手固定集，8/8 用例通过，状态、拒答、引用召回、来源完整性和用例通过率均为 1.0。API、助手页面和 `scripts/run_assistant_evaluation.py` 均可复跑；详细结果见 `docs/reports/assistant-security-vertical-baseline-2026-09-04.md`。

当前机器没有 Docker、本地 BGE 权重或运行中的 Milvus，且只有单张 4 GB RTX 3050 Ti；仓库的 Qwen3-30B FP8 配置要求两张 24 GB GPU。因此完整 BGE/Milvus/Reranker/Qwen 当前版本复验属于环境阻塞，不得用 2026-07-28 的历史快照或本次抽取式结果替代。

完成标准：固定助手用例在正常、降级、冲突、过期和越权场景均有稳定且可解释结果，引用能回到实际检索块。
