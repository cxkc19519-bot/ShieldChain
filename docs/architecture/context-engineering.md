# 多智能体上下文工程

> 文档状态：当前参考文档。若与历史计划或验收快照冲突，以本文件和 `docs/README.md` 为准。

## 模型

所有智能体读取一份经过权限过滤的结构化案件共享上下文，同时拥有角色私有上下文。不得向每个智能体复制完整聊天、日志或文档。

## 共享案件上下文

包含案件 ID、用户目标、阶段、已确认事实、证据摘要与引用、待验证假设、风险、计划、步骤状态、处置状态及预算。只有经过验证和分类的信息可以进入共享事实区。

## 角色私有上下文

- 调查：时间线、实体关系和调查假设。
- 检索：原问题、改写查询、候选文档和引用。
- 处置：批准计划、风险判断和工具结果。
- 验证：期望状态、观测结果和失败分类。
- 报告：报告结构、确认事实、引用和审计摘要。

## 上下文装配顺序

系统规则、安全边界、当前子任务、允许动作、案件摘要、相关证据、按需知识、必要交接信息、输出 Schema。

装配器必须执行 Token 预算、权限过滤、相关性排序、去重、时间衰减、来源标记、提示注入隔离和敏感字段脱敏。

## 结构化交接

交接至少包含发送方、接收方、结论、证据引用、置信度、开放问题和建议动作。自然语言说明可以作为补充，但不能替代结构化字段。

## 分层记忆

- 工作记忆：当前步骤，结束后释放。
- 案件记忆：事件生命周期内保持，关闭后归档。
- 经验记忆：人工确认、脱敏后才可进入长期知识库。
- 会话记忆：用户偏好和对话摘要，与安全证据隔离。
- 审计记忆：模型、提示、工具和审批版本，仅作审计用途。

## 压缩规则

- 确认事实转为结构化字段。
- 长日志保留不可变原文引用，只注入关键片段。
- 重复信息合并，过期假设退出活动上下文但保留审计。
- 模型摘要必须保留有效证据引用；关键证据、审批和工具结果不能只保存摘要。

## 质量指标

关键证据召回率、无关上下文比例、压缩一致性、交接完整率、提示注入阻断率、事实漂移率、Token 与费用；权限泄漏率必须为零。
