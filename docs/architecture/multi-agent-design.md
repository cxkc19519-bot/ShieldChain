# 多智能体设计

> 文档状态：当前参考（更新于 2026-08-22）。现行运营报告链路使用模型驱动的 ReAct 选择，不采用固定角色顺序。

## 专业角色

| 角色 | 职责 | 可产生的公开结果 |
| --- | --- | --- |
| 总控智能体 | 观察当前事实、选择下一角色、控制预算和结束条件 | 选择原因、交接摘要 |
| 告警分诊智能体 | 分级、去重、排序并识别需优先处理的告警 | 告警优先级与依据 |
| 威胁研判智能体 | 关联告警、漏洞和攻击迹象，区分事实与待证实线索 | 风险判断、证据缺口 |
| 知识检索智能体 | 按需调用 RAG，检索规范、ATT&CK 和处置依据 | 带来源的检索摘要 |
| 响应规划智能体 | 提出需要人工确认的处置建议 | 建议、前置条件、风险 |
| 验证智能体 | 定义实施后需要检查的日志、指标和验收条件 | 验证清单，不宣称已执行 |
| 报告智能体 | 汇总事实、限制、建议和引用 | 中文报告摘要 |

安全运营报告智能体是对上述团队的任务入口，负责时间参数校验、工具选择、协作运行、综合分析、排版和 HTML/Markdown 回显。

## ReAct 循环

1. 总控读取服务端裁剪后的公开观察。
2. 模型从剩余角色或可用工具中选择下一步，并输出严格结构化结果。
3. 服务端校验角色、工具、参数、预算和循环状态。
4. 专业角色读取授权范围内的工具结果，形成公开摘要和交接包。
5. 总控再次观察，决定继续、转交、补充检索或结束。
6. 达到预算、重复循环、模型异常或无可用工具时安全降级并转人工。

角色顺序不是硬编码业务流程；但权限、预算、停止条件和输出模式始终由服务端确定。

## 工具选择

四类进程内运营工具（当前代码使用 MCP façade 命名）不是强制全部调用。智能体根据任务选择：

- `events`：事件与关联调查记录；
- `alerts`：Wazuh 等来源的告警；
- `vulnerabilities`：漏洞与暴露线索；
- `weak_passwords`：弱密码风险统计。

工具返回值先经过大小、字段和敏感性裁剪，再提供给模型。工具异常不会伪造成空数据或成功结果。

## 记忆与上下文

- 共享上下文保存公开事实、已调用工具、交接和预算。
- 私有角色上下文按租户、运行和角色隔离。
- 智能助手会话记忆与安全运营运行轨迹分开持久化。
- 历史报告可进入 RAG，但不能直接成为执行授权。

## 降级

模型不可用、结构化输出无效、RAG 不可用或工具失败时，系统保留已确认的确定性结果，明确标注缺口并转人工；不得编造工具结果、验证成功或处置完成。
