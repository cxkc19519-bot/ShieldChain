# 系统架构

## 架构风格

初版采用“模块化单体＋可插拔外部服务”。本机只常驻 React 前端和 FastAPI 后端，多个智能体作为后端内部有清晰接口的模块运行。后续可按负载和企业部署要求拆分服务。

## 核心模块

- 前端：运营总览、事件调查、智能体工作台、知识库、处置中心、报告和审计。
- API 层：认证、授权、输入校验、限流、任务接口和实时进度。
- 超级智能体编排器：显式状态机、任务规划、角色调度、反馈和重新规划。
- 专业智能体：告警、调查、知识检索、响应处置、验证和报告。
- 上下文装配器：权限过滤、相关性选择、Token 预算、压缩和结构化交接。
- RAG 子系统：解析、分块、索引、改写、混合检索、重排、引用和评测。
- 受控 ReAct 循环：结构化观察、固定失败分类、确定性计划差异、服务端预算/循环检测、崩溃恢复和人工接管。
- 可信工具网关：工具注册、策略校验、审批、执行、幂等和审计。
- 仿真层：流量、端点、身份、日志以及防火墙、EDR、账号工具模拟器。
- 状态与审计：SQLite 初版存储，保留迁移 PostgreSQL 的仓储接口。

## 设计原则

- 模型负责语义任务，权限、审批、工具参数和状态转换由确定性代码负责。
- 所有外部能力通过适配器接入。
- 事实、假设、模型结论、知识引用和工具结果采用不同数据类型。
- 不展示隐藏思维过程，展示可审计的“证据—判断—行动—结果”轨迹。
- 原始证据不可覆盖；所有关键状态变更可追溯。

## 主数据流

告警进入系统后建立案件；编排器并行收集多源证据，调用 RAG 获得知识依据，形成结构化研判与处置计划。可信工具网关执行风险校验和必要审批，工具执行后由验证智能体再次观测。验证失败进入受控 ReAct 循环：只保存结构化观察、分类、预算、计划差异和引用，不保存隐藏思维过程；重新规划只产生 `proposed:*`，真实执行始终回到可信工具网关。未知变更结果只能查询注册状态，预算耗尽、循环、审批拒绝和不确定状态转人工；只有实际验证成功才继续报告闭环。

所有循环、观察、分类、计划、决策和人工控制均 tenant-bound 并使用 revision/CAS。公开轨迹采用字段白名单，不返回 tenant、操作主体、原始适配器结果、提示、思维链、凭据或敏感证据 payload。

## 完整前端与公开投影边界

Phase 7 前端由统一应用壳和六个工作区组成：运营总览、事件调查、智能体与 ReAct 工作台、知识库工作台、处置中心、报告与审计。页面只在 URL 与 `sessionStorage` 中保存公开资源标识和展示偏好；tenant、principal、授权上下文、内部风险/预算、凭据及原始适配器结果始终由服务端持有。

各工作区只消费经过白名单投影的 API 资源：事件页展示时间线与证据摘要，智能体页展示结构化步骤和人工控制，知识库页展示文档、检索结果和引用，处置页展示审批与工具轨迹，报告页展示只读汇总和审计记录。任何页面都不得渲染提示词、思维链、凭据、私有 payload 或服务端身份字段。

统一壳负责路由焦点、加载/错误语义、请求取消和失败关闭；样式合同覆盖 320px 最小视口、键盘导航、语义标题、ARIA 状态及减少动画偏好。Phase 7 smoke 先串联阶段 2–6 离线链路，再在禁用网络访问的前端环境中访问六个真实路由；它不构成真实云模型、自主规划器或安全设备链路的验收证据。

## 运行状态与可观测边界

Liveness 只反映进程响应能力；readiness 是数据库连通、Alembic 精确 head 和应用生命周期接受状态的合取，迁移缺失、落后或多 revision 均失败关闭。版本投影只公开服务、包版本和期望 schema revision，不包含部署或源代码管理元数据。

应用启动先恢复中断调查，再接受请求；关闭先撤销接受状态，再执行后台运行器的超时等待和取消。已经进入工作线程的短步骤不能被强制终止，由持久状态和下次启动恢复保证不虚报完成。

日志采用公开字段白名单与递归脱敏：request/correlation 标识可以保留，tenant、principal、actor、凭据、提示、推理轨迹以及原始证据或适配器 payload 不得进入日志输出。


## 容器部署拓扑

Compose 部署保持模块化单体边界：浏览器只连接宿主机回环地址上的非 root Nginx；Nginx 提供前端静态资源并把 `/api/` 转发到仅存在于内部网络的 FastAPI；一次性迁移服务与 FastAPI 共享后端镜像和 SQLite 命名卷。后端 readiness 通过后，前端才开始接受依赖 API 的流量。

容器默认使用只读根文件系统、删除全部 capabilities、启用 `no-new-privileges` 并使用固定非 root UID。可写目录仅限明确声明的 `tmpfs` 和 SQLite 命名卷。配置不包含密钥；真实凭据必须由目标平台在运行时注入。

该拓扑面向单机比赛演示和可复现验收。SQLite 命名卷不支持多副本写入或高可用承诺，未来生产扩展需要替换为受管关系数据库，并在授权环境中完成镜像、网络、备份恢复与真实适配器验证。

当前开发环境没有 Docker CLI，拓扑仅由静态合同覆盖，容器运行边界明确记录为 `DOCKER_RUNTIME_TESTED=False`。
