# ShieldChain 系统设计

> 文档状态：当前参考（更新于 2026-08-23）。早期固定钓鱼仿真和独立事件调查页已退役。

## 目标

ShieldChain 将真实安全数据、知识检索、专业智能体协作和人工监督组合为可审计的安全运营分析系统。模型负责观察、规划、工具选择和建议生成；系统策略负责授权、数据裁剪、持久化和处置边界。

## 逻辑分层

1. **数据接入层**：Wazuh 告警收件箱、离线 NTA 数据集、知识库文档和历史调查报告。
2. **分析服务层**：告警归一化、关联窗口、RAG 混合检索、语义分块、向量检索和重排。
3. **智能体层**：总控、告警分诊、威胁研判、知识检索、响应规划、验证和报告七个角色，以 ReAct 方式动态选择下一角色和工具。
4. **工具层**：事件、告警、漏洞、弱密码四类进程内只读 Agent Tool，以及独立受控的可信处置工具网关；标准 MCP Server 已复用四类 Provider 并具备 JWT/JWKS 鉴权，外部 MCP 具备管理员固定发现、运行快照和受控只读 Provider。真实身份平台/peer/TLS 联调仍待实施。
5. **应用层**：运营总览、安全运营报告、实时告警、知识库、历史报告、智能助手和受控轨迹页面。

## 主要数据流

```text
Wazuh / NTA / 本地文档
        ↓
归一化、去重、持久化与访问控制
        ↓
总控智能体观察公开状态
        ↓
按任务选择专业角色与只读工具
        ↓
RAG 依据 + 工具结果 + 历史报告
        ↓
结构化结论、建议、审计轨迹与报告预览
        ↓
人工复核；如需处置则进入独立审批和可信工具边界
```

## 模型接入

后端通过 OpenAI 兼容接口访问模型，可配置外部 DeepSeek，也可使用 `compose.local-llm.yaml` 启动本地 vLLM `Qwen3-30B-A3B-Instruct-2507-FP8`。业务代码不依赖特定供应商名称；模型不可直接获得数据库连接、Shell、凭据或不受控网络能力。

## 持久化

- SQLite 保存应用元数据、告警收件箱、通用智能体运行、运营报告关联、智能体轨迹和调查状态；容器部署使用命名卷。
- `agent_runs` 是调查与运营报告的租户化通用父运行；`investigation_runs` 和 `operations_runs` 保存各自专属字段，新运营报告正文暂时仍保存在受控本地 JSON 文件中。
- `agent_tool_calls` 保存内部与 MCP 调用的公开审计投影；运行中记录在服务恢复时转为结果未知，原始工具载荷和凭据不进入该表。
- 知识库原文、分块、索引状态和助手会话使用持久化目录。
- Milvus 保存向量索引；BM25 和本地检索状态由 RAG 服务维护。
- `.env`、数据库、模型缓存和真实告警不得进入版本库。

## 部署拓扑

- Windows 本地：`python app.py` 启动 FastAPI 与 React 开发服务。
- 基础容器：`compose.yaml`。
- 服务器持久化覆盖：`compose.server.yaml`。
- 双 GPU 本地模型覆盖：`compose.local-llm.yaml`，回环接口 `127.0.0.1:8001`。
- Wazuh/OpenSearch 和模型服务可位于服务器，本地浏览器通过端口转发访问前端。

## 安全边界

- 前端只显示公开摘要、引用、工具名称、状态和受控轨迹，不显示私有提示词或思维链。
- 四类 MCP 工具只读；响应规划智能体只能提出建议。
- 任何真实处置必须经过策略、审批、可信工具网关、幂等控制和执行后验证。
- 共享 GPU 服务器不得自动终止、修改或抢占其他用户进程。
