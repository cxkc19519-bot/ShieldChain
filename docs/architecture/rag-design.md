# RAG 设计

> 文档状态：当前参考（更新于 2026-08-08）。RAG 同时服务于知识检索智能体和智能助手。

## 数据来源

- 用户上传并发布的本地知识库文档；
- 安全垂直知识库示例，包括监管基线、0day 响应和 MITRE ATT&CK；
- 已完成并允许检索的历史调查报告。

所有知识库、文档版本、分块和索引状态持久化保存，重启后无需重新上传。

## 入库链路

1. 文件名、类型、大小和内容安全检查；
2. 格式解析与文本规范化；
3. 标题、段落和长度规则生成候选块；
4. 配置模型时进行 LLM 语义边界优化；
5. 结构化结果校验、偏移修复、去重和质量检查；
6. LLM 失败时使用规则分块并明确记录降级原因；
7. Embedding、BM25 和 Milvus 索引；
8. 发布版本成为默认检索版本。

“LLM 分块失败，已使用规则分块”表示文档入库成功但语义优化失败，不表示 LLM 分块成功。

## 检索链路

1. 查询规范化和可选问题改写；
2. BM25 关键词召回；
3. BGE-M3 向量召回；
4. 融合去重；
5. BGE Reranker 重排；
6. 权限、版本和引用过滤；
7. 证据不足时明确拒答或给出限制。

本地持久化检索可在云链路不可用时继续工作；界面必须显示真实采用的检索模式和降级状态。

## 模型与存储

- Embedding：BGE-M3；
- 向量数据库：Milvus；
- Reranker：BGE Reranker；
- 语义分块模型：任意 OpenAI 兼容模型，可为 DeepSeek 或本地 Qwen/vLLM；
- 文档和会话原始数据：本地持久化目录；
- 元数据：SQLite。

## 安全要求

- 不接受远程 URL 或服务端本地路径作为上传输入；
- 检索结果必须携带文档、版本、块号和可公开引用；
- 删除知识库或文档时同步删除关联原文、分块和索引；
- 历史报告进入知识库前执行字段裁剪，不包含凭据、私有提示词和原始敏感载荷；
- 模型输出不能替代来源证据。
