# 盾链智御需求与系统设计

> 文档状态：历史规划/设计归档。用于追溯阶段性决策，不代表当前运行方式；现行架构以 `docs/README.md` 及各目录现行文档为准。

## 1. 背景与目标

本项目响应“AI+安全大模型平台的智能体研究”赛题，优先完成占 70 分的场景化安全智能体，并实现占 20 分的领域知识增强与工具扩展，以及占 10 分的超级智能体挑战任务。核心场景为多源告警研判与自动处置闭环。

主演示从钓鱼附件触发可疑 PowerShell 开始，关联恶意外联、账号失陷和服务器异常访问，经多智能体调查、RAG 知识增强、可信工具调用、处置验证和必要的重新规划，最终关闭事件并生成报告。

## 2. 已确认约束

- 暂无深信服平台、安全数据和工具接口，初版使用仿真数据与工具。
- LLM 使用 DeepSeek API，外部能力必须通过适配器接入。
- RAG 使用云端 BGE-M3 Embedding、托管 Milvus、BM25 混合召回和云端 BGE-Reranker-v2-m3。
- 初版在 Windows 本机直接运行，后续提供 Docker Compose。
- 前端简洁直观，以淡蓝色为主。
- 采用垂直切片、小步闭环的开发方式。

## 3. 总体架构

系统采用模块化单体和可插拔外部服务。React 前端访问 FastAPI 后端；后端包含编排器、专业智能体、上下文装配器、RAG、可信工具网关、仿真工具、状态和审计模块。多个智能体不作为多个常驻进程运行。

超级智能体使用显式状态机协调告警、调查、检索、处置、验证和报告角色。模型负责语义分析，确定性代码负责权限、参数、状态和风险控制。所有关键结论和动作形成“证据—判断—行动—结果”轨迹。

## 4. 多智能体闭环

告警进入后建立案件并收集流量、端点、身份和日志证据。RAG 提供 ATT&CK、CVE、处置手册及合规依据。证据充分后生成结构化处置计划，经可信工具网关风险判断和审批后执行。验证智能体重新观测目标状态；失败则返回结构化原因并在预算内重新规划，成功则生成报告。

只读和低风险操作自动执行；真实模式中的中高风险操作受审批控制；仿真比赛模式允许全自动，但不绕过校验和审计。

## 5. 上下文工程

所有智能体共享经过权限过滤的结构化案件上下文，并分别拥有角色私有上下文。上下文装配器按当前子任务选择案件摘要、相关证据、知识和交接信息，执行 Token 预算、去重、脱敏和提示注入隔离。

智能体之间使用含证据引用的结构化交接包。工作、案件、经验、会话和审计记忆相互隔离；未经人工确认的模型输出不得写入长期知识库。上下文压缩不能丢弃原始证据、审批和工具结果引用。

## 6. 产品级 RAG

首批支持 PDF、DOCX、Markdown、TXT、HTML、CSV 和 XLSX。文档经过安全检查与解析后，先按结构和 Token 规则产生候选块，再由 DeepSeek 优化语义边界并由确定性代码校验。模型失败时规则块降级入库并标记，后续支持重试升级。

查询经过纠错、术语规范化、指代消解、上下文补全、实体提取和多查询扩展。BGE-M3 与 Milvus负责向量召回，BM25 负责关键词召回，使用 RRF 或经评测的权重融合，完成权限过滤后由 BGE-Reranker-v2-m3 重排。回答必须携带文档、章节、页码、片段、版本和评分；证据不足、冲突或过期时拒答或请求补充。

RAG 以固定中英文基准集评测解析、分块、Recall@K、MRR、nDCG、重排增益、引用、忠实度、拒答、跨语言一致性、延迟、费用和失败率。

## 7. 可信工具调用

智能体不能直接操作设备。可信工具网关校验工具身份、调用者权限、参数 Schema、目标范围、风险、审批、幂等、频率、超时和重试。工具只接受结构化参数，不执行任意 Shell 或模型生成代码。

调用前绑定案件、计划、证据和预期状态；调用后记录结果并再次验证。高风险失败先查询当前状态，不盲目重复。系统支持暂停、取消、恢复、紧急停止和全局关闭自动化。

## 8. 前端设计

采用淡蓝色、白色和浅灰色的专业运营界面。左侧为运营总览、事件调查、智能体工作台、知识库、处置中心、报告与审计导航；主体优先展示案件状态、攻击证据链、智能体协作轨迹、工具风险和验证结果。红色仅用于高危和失败，橙色用于中风险，颜色不能成为唯一状态表达。

## 9. 失败与降级

- DeepSeek 不可用时限次重试，无法安全继续的任务暂停。
- LLM 分块失败时使用规则块并标记降级。
- Embedding 或 Reranker 失败时批次可恢复，不伪造索引或评分。
- Milvus 不可用时可显式降级为 BM25，回答显示降级状态。
- 工具失败先观察状态，再重试、重新规划或转人工。
- 达到步骤、循环、时间、Token、费用或工具预算时安全终止。
- 前端断线不丢失后端任务状态。

## 10. 测试

测试覆盖单元、外部服务集成、工作流、RAG 评测、安全、前端和三分钟演示回归。默认测试不产生真实云费用；真实服务测试显式开启并限制费用。重点验证提示注入、越权工具、恶意文件、密钥泄漏、上下文权限、事实漂移、证据不足和失败重新规划。

## 11. 开发顺序

按工程基础、最小事件闭环、产品级 RAG、多智能体与上下文、可信工具调用、ReAct、完整前端、加固与比赛交付八个阶段推进。每阶段通过功能验收、测试、安全检查并更新文档和日志后才进入下一阶段。

## 12. 交付与成功标准

系统必须在 Windows 本机稳定运行并可迁移至 Docker Compose；主演示可重复完成调查、处置、验证和报告；重要结论可追溯；高风险动作不能绕过监督；失败可安全降级、重新规划或转人工；比赛要求的代码、文档、PPT 和三分钟视频完整。
