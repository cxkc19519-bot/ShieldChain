# 阶段 4：多智能体与上下文工程设计

## 1. 目标

在现有确定性事件闭环和产品级 RAG 之上，建立可审计、最小权限、可恢复的多智能体协作基础。所有角色共享一份经过权限过滤的结构化案件上下文，同时只拥有完成自身职责所需的私有上下文。

阶段 4 不实现阶段 5 的可信工具网关，也不实现阶段 6 的 ReAct 自主重规划。响应角色只能提出结构化动作计划，不能直接操作安全设备。

## 2. 角色与信任边界

- 超级智能体：确定子任务、调度角色、汇总结构化结果并依据状态机推进。
- 告警研判：聚合、去重、风险分级和误报判断。
- 威胁调查：关联实体、时间线、证据和待验证假设。
- 知识检索：调用阶段 3 RAG 领域服务，只返回带可信引用的结果或结构化拒答。
- 响应规划：形成待审批的结构化动作计划，不调用工具。
- 验证：比较期望状态与可信观测结果。
- 报告：只依据已确认事实、可信引用和审计记录生成报告结构。
- 安全监督器：确定性策略组件，不是拥有任意权限的 LLM 角色。

多智能体是模块化单体内的角色组件，不部署为多个常驻进程。

## 3. 上下文模型

### 3.1 共享案件上下文

共享内容包括案件 ID、阶段、用户目标、已确认事实、证据与知识引用、待验证假设、风险、计划、步骤状态、处置状态和预算。只有已验证且有可追溯引用的信息能进入已确认事实区。

### 3.2 角色私有上下文

每个角色拥有独立、最小必要的私有结构；角色不能读取或修改其他角色的私有上下文。私有结论不能直接升级为共享事实。

### 3.3 分层记忆

- 工作记忆：仅用于当前步骤，结束后释放。
- 案件记忆：在案件生命周期内保存，关闭后归档。
- 会话记忆：仅保存用户偏好和对话摘要，与安全证据隔离。
- 审计记忆：保存模型、提示策略、工具和审批版本摘要，不保存思维链。
- 经验记忆：只有人工确认且脱敏后才能进入长期知识库。

禁止保存或展示原始提示、思维链、密钥和脱敏前敏感内容。

## 4. 上下文装配

固定装配顺序为：系统规则、安全边界、当前子任务、允许动作、案件摘要、相关证据、按需知识、必要交接、输出 Schema。

装配器必须先做租户、主体、角色、敏感级别和权限标签过滤，再执行相关性排序、去重、时间衰减和 Token 裁剪。系统规则与安全边界不可截断；证据和 RAG 文本始终放在不可信数据包络中，不能覆盖系统指令。

超出预算时必须返回显式降级或拒绝，不得静默越界。关键证据、审批和工具结果不能只保留模型摘要，必须保留不可变引用。

## 5. 结构化交接

交接至少包含发送角色、接收角色、结论、证据/知识引用、置信度、开放问题和建议动作。接收方把上游结论视为待验证声明，必须重新解析引用，不能直接当作事实。

交接历史只追加、不可覆盖；跨租户、跨案件、失效或伪造引用默认拒绝。无引用结论不能标记为高置信。

## 6. 持久化与并发

案件上下文、已确认事实、角色私有上下文、交接和执行摘要使用显式租户边界。共享上下文采用 revision/CAS 防止并发覆盖；事实、交接和执行记录的 schema 为只追加仓储准备，但数据库层不使用触发器禁止 UPDATE/DELETE，Task 3 由仓储强制只追加并测试；状态变化与现有事件审计在同一事务提交。

现有仿真事件需要由服务端可信配置绑定 demo tenant，客户端不得提交或覆盖 tenant/principal。

## 7. 协作状态机

阶段顺序为研判、调查、按需检索、响应规划、等待可信执行边界、验证、报告。所有转换由确定性白名单控制。

达到步骤、循环、时间、Token、费用或工具调用预算时安全终止；证据不足、来源冲突、关键依赖不可用且没有安全降级时转人工判断。阶段 4 不进行自由 ReAct 循环。

## 8. 安全与质量指标

- 权限泄漏率必须为零。
- 共享事实必须有可信引用，事实漂移测试必须通过。
- 交接字段完整率必须为 100%。
- 提示注入内容只能作为不可信数据，不能改变允许动作或输出 Schema。
- 同一输入、策略和预算必须产生稳定的装配与状态转换。
- 默认测试离线、无云费用，不能把离线替身描述为真实服务验收。

## 9. 阶段出口

完成领域模型、租户化持久化、仓储、权限/脱敏、上下文装配、分层记忆、结构化交接、专业角色、超级智能体状态机、只读协作轨迹与 Windows 离线 smoke；完整测试、安全评测、迁移往返、文档和开发日志全部通过后，才能进入阶段 5。
