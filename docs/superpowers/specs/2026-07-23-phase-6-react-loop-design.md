# 阶段 6：受控 ReAct 自主闭环设计规格

> 文档状态：历史规划/设计归档。用于追溯阶段性决策，不代表当前运行方式；现行架构以 `docs/README.md` 及各目录现行文档为准。

## 1. 目标与边界

阶段 6 在阶段 4 的确定性多智能体状态机和阶段 5 的可信工具执行边界之上，增加可恢复、可审计、预算受限的观察—反馈—重新规划闭环。系统可根据结构化工具结果和执行后验证选择继续验证、查询状态、修改计划或转人工，但不能形成自由无限循环。

本阶段不保存或公开模型思维链，不让模型直接调用适配器，不执行模型生成的代码、Shell 或任意 HTTP，不连接真实安全设备，也不提前实现阶段 7 完整前端。默认测试继续完全离线且无云费用。

## 2. 结构化循环模型

每次循环只追加以下公开安全记录：

- `observation`：来源类型、绑定的调用/验证/证据引用、公开安全状态与稳定原因码；
- `assessment`：固定失败类别、可恢复性和置信度，不含私有提示或自由推理文本；
- `plan_revision`：基于上一个计划的版本、保留/删除/新增的白名单动作及引用；
- `decision`：`continue_verification`、`query_status`、`retry_read_only`、`replan`、`manual_review` 或 `complete`；
- `budget`：步骤、循环、墙钟时间、Token、费用和工具调用的服务端计数快照。

记录必须绑定 tenant、case、run 和 revision。公开 API 只返回上述投影，不返回 tenant、principal、原始工具输出、模型提示、思维链、凭据或租约令牌。

## 3. 失败分类

分类器只接受受信领域对象，不解析任意异常文本。固定类别包括：

- `verification_failed`：工具已执行但预期状态未达到；
- `verification_inconclusive`：无法确认最终状态；
- `execution_failed`：适配器明确报告失败；
- `execution_outcome_unknown`：变更动作超时或结果未知；
- `approval_rejected`：人工明确拒绝；
- `emergency_stopped` / `automation_disabled`：控制面阻止继续；
- `dependency_unavailable`：只读依赖不可用且无可信降级；
- `evidence_insufficient` / `evidence_conflict`：证据不足或冲突；
- `budget_exhausted` / `loop_detected`：监督器停止条件。

未知状态默认归类 `unclassified_failure` 并转人工，不允许模型自造可重试类别。

## 4. 重新规划规则

重新规划器是确定性策略，不是自由代理循环。输入为当前不可变计划、失败分类、受信观察、注册表能力和剩余预算；输出为严格 Schema 的 `PlanRevision`。

- 变更动作结果未知时只能先调用配对只读查询，不能重放变更动作。
- 明确失败且目标状态未改变时，可在白名单替代动作中产生新提案；新动作必须重新通过可信工具策略、审批、幂等和验证。
- 审批拒绝、紧急停止、自动化关闭、证据冲突和不可分类失败直接转人工。
- 只读失败仅在注册表允许且预算充足时重试。
- 每个修订必须保留原始计划 ID、父 revision、失败原因和证据/验证引用，禁止删除历史。

## 5. 循环和预算监督

预算由服务端持有并使用 CAS 更新。除阶段 4 已有 step/token 外，本阶段强制：

- `loop_limit` 和 `loops_used`；
- `time_limit_seconds` 和基于 UTC 起止时间的累计值；
- `cost_limit_usd` 和非负确定性计量；
- `tool_call_limit` 和阶段 5 持久化调用/尝试计数；
- 同一规范化观察 + 计划摘要重复时触发 `loop_detected`。

任何预算达到或预计超限时，在执行新角色或工具前停止并转人工。客户端提供的计数、风险或剩余预算一律忽略。

## 6. 持久化与并发

新增循环运行、观察、分类、计划修订和决策表。循环运行使用 revision/CAS；其他记录只追加。数据库约束绑定 tenant/case/run，计划修订与观察必须引用同一循环。事务应原子提交观察、分类、修订、决策、预算和事件审计，失败时不产生半步状态。

恢复扫描只处理明确可恢复的 `running` 循环；过期执行租约继续委托阶段 5 恢复服务。多个 worker 对同一 revision 竞争时最多一个提交成功，失败方重读状态，不重复工具调用。

## 7. 编排接线

阶段 4 编排器在工具未验证时不再一律立即终结：它把实际 `TrustedToolCall`、`ToolVerification` 和服务端预算交给阶段 6 决策器。决策器可以进入只读状态查询、重新规划或人工复核；只有实际 `verified` 才继续报告闭环。

响应角色仍只能输出 `proposed:*`，阶段 6 重新规划也只产生 proposed actions。真正执行继续由阶段 5 网关完成。

## 8. API 与可观察性

提供 tenant-bound 只读循环轨迹 API，展示循环 revision、结构化观察、分类、决策、预算、计划差异和引用。人工接管沿用服务端身份边界，并允许操作员确认接管/恢复；不得通过 HTTP 注入 tenant、角色、权限、分类、风险或预算。

日志和审计使用稳定 reason code 与 request ID，不记录原始适配器结果、提示、思维链、凭据或敏感证据 payload。

## 9. 验收标准

阶段 6 只有在以下条件全部满足后完成：领域合同、迁移与仓储、失败分类、确定性重新规划、预算与循环检测、并发恢复、阶段 4/5 接线、只读 API、离线 smoke、安全回归、迁移往返、完整门禁、文档和开发日志全部通过。真实模型自主规划和真实设备路径必须明确标记未测试。
