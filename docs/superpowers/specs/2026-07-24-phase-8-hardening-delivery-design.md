# 阶段 8：加固与比赛交付设计

## 1. 目标与边界

阶段 8 把阶段 2–7 的离线产品闭环提升为可测量、可部署、可审计、可复现的比赛交付包。加固不能通过放宽 tenant、审批、工具网关、ReAct 预算或公开字段白名单来换取便利；任何真实云模型和安全设备仍需显式授权，离线结果不得冒充真实链路验收。

## 2. 性能与容量基线

使用固定本地数据集建立 API、RAG、前端构建和端到端演示的确定性基线。报告样本量、分位数、机器/运行时信息及阈值，避免只记录单次平均值。门禁以宽松但明确的回归预算失败关闭；性能测试不联网、不产生费用，不要求专用硬件。

## 3. 应用安全加固

覆盖安全响应头、可信代理边界、CORS/Host、请求与上传大小、内容类型、超时、日志脱敏、错误最小化、依赖审计和静态安全检查。开发模式保留本地易用性，生产 profile 对缺失密钥、宽泛来源、调试开关和模拟适配器失败关闭。

## 4. 运行与可观测性

区分 liveness、readiness 和公开版本信息；就绪检查验证数据库迁移及必要配置但不泄漏连接串或密钥。结构化日志携带公开 request/correlation 标识，不记录 tenant 私有上下文、凭据、提示、思维链或原始证据 payload。关闭流程应有界并停止接受新工作。

## 5. 容器化部署

为后端和前端提供固定版本、非 root、多阶段构建的 Dockerfile，使用 Compose 编排健康检查、只读配置和具名持久卷。容器不得内置 `.env`、凭据、开发数据库或本机绝对路径；部署 smoke 使用离线替身并验证启动、迁移、六工作区和安全边界。

## 6. 交付文档与演示资产

交付源代码说明、总体设计、开发说明、测试报告、项目总结、答辩 PPT 和三分钟视频工程/成片。所有指标、截图和演示结论必须可追溯到提交、命令或测试输出；未验证的真实模型、设备、生产并发和云部署显式标注。

## 7. 自动化与可复现性

Windows 本地完整门禁保持可用，同时新增容器与交付物合同。所有脚本支持路径含空格、临时目录安全清理、首错退出和实时开关隔离。CI 只运行离线路径，不读取未授权 secret，不自动推送或发布。

## 8. 任务顺序

1. 建立性能、安全与交付物基线和机器可读预算。
2. 加固 HTTP、上传、CORS/Host 和生产 profile。
3. 优化并验证数据库、RAG 与聚合查询性能。
4. 完善 readiness、版本、日志和有界关闭。
5. 构建后端/前端非 root 容器与 Compose。
6. 新增容器离线 smoke、CI 和供应链合同。
7. 完成源代码、设计、开发、测试和部署文档。
8. 制作项目总结与答辩 PPT。
9. 制作三分钟视频脚本、工程和成片。
10. 执行完整门禁、打包清单和最终验收。

## 9. 验收标准

- 固定性能场景有机器可读阈值、分位数和回归测试。
- 生产 profile 对不安全配置失败关闭，公开错误与日志不泄漏敏感内容。
- Docker Compose 可从干净环境构建、迁移、启动并通过离线 smoke，服务以非 root 运行。
- Windows 本地开发和阶段 2–7 smoke 不退化。
- 文档、PPT、视频和打包清单存在且通过自动合同检查。
- 完整后端、前端、迁移、RAG、安全、脚本、容器和 Phase 8 smoke 通过。
