# 阶段 5：可信工具调用设计规格

## 1. 目标与边界

阶段 5 在阶段 4 的 `awaiting_trusted_execution` 边界后增加确定性的可信工具网关。任何智能体、模型或 HTTP 客户端都不能直接取得工具适配器、设备凭据或任意代码执行能力。网关只接受由服务端绑定案件、计划、调用者和证据的结构化请求。

本阶段实现工具注册、策略、审批、幂等、审计、超时、受限重试、执行后验证、暂停/取消/恢复、紧急停止和全局自动化开关，并接入本地仿真工具。阶段 6 的 ReAct 自主重规划、真实安全设备、模型生成代码、任意 Shell、任意 HTTP/URL 工具和生产密钥管理不在范围内。

## 2. 信任模型

- tenant、principal、角色、案件、调查运行和执行模式仅来自服务端可信上下文；请求体不能覆盖。
- 响应规划智能体的 `proposed:` 输出只是候选，不是授权。服务端必须把它解析为已知动作枚举并重新绑定目标和证据。
- 工具注册表只包含编译期允许的名称、版本、参数 Schema、风险级别、目标类型、超时、最大重试和验证器；未知工具、未知版本或额外参数默认拒绝。
- 工具适配器只接收经过校验的不可变参数对象，不接收 prompt、代码、Shell、URL、凭据或自由文本命令。
- 工具返回值和错误详情是不可信数据；持久化与公开展示只使用 allowlist 投影，进入模型上下文前复用注入隔离。

## 3. 领域状态

工具调用采用只前进状态机：

`proposed -> policy_checked -> awaiting_approval|approved -> executing -> verifying -> succeeded|failed|needs_review`

另有 `rejected`、`cancelled` 和 `emergency_stopped` 终态。并发更新使用 revision/CAS；状态跳转必须在白名单内。批准不能隐式等于执行，执行不能隐式等于验证成功。

核心不可变合同包括：

- `ToolDefinition`：名称、版本、参数类型、目标类型、风险、权限、超时、重试和验证策略。
- `TrustedToolRequest`：调用 ID、幂等键、案件/运行/计划、调用角色、工具版本、结构化参数、预期状态、回滚策略、证据引用和创建时间。
- `PolicyDecision`：允许/拒绝/需审批、稳定原因码、策略版本、风险和有效期。
- `ApprovalDecision`：批准/拒绝、审批主体、策略版本、时间、备注摘要；高风险操作实行调用者与审批者分离。
- `ToolExecutionRecord`：尝试次数、状态、开始/结束时间、结果摘要、错误分类和关联验证；不保存密钥或原始敏感输出。
- `ToolVerification`：是否达到预期状态、可信观测引用和原因码。

## 4. 工具注册与参数校验

注册表在启动时拒绝重复 `(name, version)`、不受支持的参数类型、无界字符串、动态 URL、任意代码字段、无验证器的变更类工具以及不合理的超时/重试。阶段 5 初始工具为：

- `query_firewall_state@1`：只读、自动执行；
- `block_ip@1`：仿真模式可自动批准，真实模式需要审批；
- `isolate_endpoint@1`：仿真模式可自动批准，真实模式需要审批；
- `disable_account@1`：高风险，默认人工审批，仿真模式是否自动批准由显式策略决定。

参数使用具体类型（IPv4、受限主机名、受限账号标识）和长度限制。目标必须由案件中同租户的已确认证据解析，不能只相信模型字符串。

## 5. 策略与审批

策略检查顺序固定：全局开关/紧急停止、调用状态、工具身份与版本、调用者权限、案件/运行绑定、证据完整性、参数 Schema、目标范围、风险策略、速率与预算、审批要求。

策略返回稳定原因码，不暴露内部异常。只读和低风险操作可自动批准；仿真模式的自动批准仍记录 `automatic_policy` 审批来源。中高风险真实模式必须有未过期、未撤销、与请求摘要绑定的批准。审批者不能修改工具参数；参数变化会使旧审批失效并重新评估。

## 6. 幂等、执行、超时与重试

- 幂等键在 tenant、run、tool 范围内唯一，并绑定规范化参数摘要；同键同请求返回已有记录，同键不同请求拒绝。
- 执行租约由 CAS 获取；崩溃恢复后先查询当前状态，再决定完成、复核或重试。
- 只读操作和明确可安全重试的低风险操作可在定义上限内重试。
- 高风险变更失败、超时或结果不确定时禁止盲目重放，必须先调用只读状态查询；不能确认时转人工复核。
- 超时只表示调用结果未知，不得报告动作未发生或成功。

## 7. 审计与持久化

每次提议、策略判断、审批、租约、尝试、结果、验证、重试、取消和紧急停止都追加审计事件。数据库保存规范化参数摘要和 allowlist 参数，不保存凭据、原始 prompt、思维链或适配器私有异常。

关键状态更新、执行尝试和审计必须在单个事务中提交。审批和执行记录只追加；调用聚合使用 CAS revision 更新。所有查询按可信 tenant/run 约束，跨租户统一返回不存在。

## 8. 控制面与恢复

支持单调用暂停、取消、恢复；全局自动化开关关闭后不再发放新执行租约；紧急停止会阻止新调用，并把尚未进入适配器的调用转为 `emergency_stopped`。已经发出的调用不能伪称已撤回，必须等待/查询结果并验证。

恢复扫描只处理明确可恢复状态：过期租约、等待审批和待验证调用。恢复动作受预算、重试策略和全局开关约束。

## 9. API 与前端

阶段 5 提供最小处置中心：只读列出调用轨迹，并允许具备服务端权限的主体提交审批、取消、恢复或紧急停止。HTTP 请求不能提供 tenant、角色、风险、策略结果或审批主体。所有变更接口需要 request ID、严格 Schema 和审计。

前端展示 proposed/approved/executing/verifying/terminal 状态、策略原因、审批、尝试、验证和引用；不得展示密钥、私有上下文、原始 prompt、思维链或未清洗工具输出。

## 10. 退出门槛

阶段 5 只有在以下条件全部满足后完成：领域合同、迁移与仓储、注册表、策略、审批、网关、幂等/恢复、仿真适配器、控制面、编排接线、API/前端、临时 SQLite 离线 smoke、安全回归、迁移往返、完整门禁、文档和当日开发日志全部通过。真实设备路径必须明确标记未测试。
