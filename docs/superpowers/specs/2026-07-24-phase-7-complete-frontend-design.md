# 阶段 7：完整安全运营前端设计

> 文档状态：历史规划/设计归档。用于追溯阶段性决策，不代表当前运行方式；现行架构以 `docs/README.md` 及各目录现行文档为准。

## 1. 目标与边界

阶段 7 把现有功能页整合成一套可演示、可追踪、可控制的安全运营工作台。前端必须复用阶段 2–6 的真实 HTTP 合同，不用硬编码成功数据掩盖后端缺失，不展示私有上下文、原始提示、思维链、凭据或原始适配器结果。

本阶段交付运营总览、事件调查、智能体工作台、知识库、处置中心、报告与审计六个完整页面，以及统一的案件/运行上下文、响应式导航、加载/空/错误状态和键盘可访问性。真实云服务、真实安全设备、SSO、生产多租户管理、WebSocket 和阶段 8 部署加固不在本阶段实现。

## 2. 信息架构

- 运营总览：系统状态、当前演示案件、调查状态、风险/证据/处置摘要和下一步入口。
- 事件调查：启动或恢复演示调查，展示事件、攻击路径、证据链、研判、处置、验证和审计时间线。
- 智能体工作台：共享案件摘要、角色状态、结构化交接、预算、可信引用，以及受控 ReAct 观察/分类/计划差异/决策轨迹。
- 知识库：上传、文档状态、检索问答、引用和显式拒答。
- 处置中心：可信工具策略、审批、执行尝试、验证、暂停/恢复/取消、紧急停止，以及循环人工接管。
- 报告与审计：基于公开案件、智能体、工具和 ReAct 投影组合只读报告；缺失数据明确显示，不推断私有字段。

## 3. 共享运行上下文

调查成功启动后，把 `incident_id` 和 `run_id` 写入 URL 查询参数与 `sessionStorage`。所有页面优先读取 URL，再读取会话存储；用户可以手工替换运行 ID。不得持久化 tenant、principal、权限、Token 或密钥。切换运行时取消旧请求，避免陈旧响应覆盖新页面。

## 4. 视觉与交互

沿用淡蓝色安全运营风格，建立统一的颜色、间距、圆角、阴影、状态徽标、按钮、输入、表格、时间线和指标卡。桌面使用固定侧栏与宽内容区；窄屏切换为顶部品牌和可换行导航。所有状态不只依赖颜色，按钮有明确 disabled/busy 文案，错误信息通过 `role=alert`，异步状态通过 `aria-live`。

## 5. 数据与安全边界

前端 API 类型必须是后端公开 Schema 的精确子集并拒绝隐式 `any`。所有写操作只发送业务字段；tenant、actor、权限、风险、分类和预算始终由服务端决定。报告页只组合已有公开 API，不读取数据库、不调用私有端点。原始 JSON 仅用于明确允许的结构化工具 before/after state，页面不通用渲染未知对象。

## 6. 支撑 API

只有在现有公开 API 无法支持页面时才新增最小只读聚合端点。端点必须 tenant-bound、字段白名单、确定排序和严格 Schema。优先让前端并行组合现有事件、审计、智能体、工具和 ReAct 轨迹，避免新建重复数据模型。

## 7. 测试策略

每个页面先写 API 与组件测试，覆盖成功、空、加载、错误、取消和敏感字段不渲染。阶段末运行 ESLint、TypeScript、Vitest、生产构建、后端完整测试、迁移往返、脚本合同和 Phase 7 smoke。Smoke 使用本地仿真案件，不联网、不产生费用、不访问真实设备。

## 8. 验收标准

- 六个导航页面均为实际功能页，无 `FuturePage` 占位。
- 从调查启动到智能体、处置、ReAct 和报告页面可沿同一 run 追踪。
- 高风险控制仍只能调用阶段 5/6 服务端边界。
- 320px–1440px 布局可用，键盘焦点、标签、状态和错误可感知。
- 所有公开页面通过敏感字段泄漏回归。
- Windows 完整门禁与 Phase 7 离线 smoke 通过。
