# 阶段 4：多智能体与上下文工程实施计划

> 文档状态：历史规划/设计归档。用于追溯阶段性决策，不代表当前运行方式；现行架构以 `docs/README.md` 及各目录现行文档为准。

按 `docs/superpowers/specs/2026-07-20-phase-4-multi-agent-context-design.md` 实施。每个任务独立测试、审查和提交；默认离线，不提前实现阶段 5 工具网关或阶段 6 ReAct。

## Task 1：核心领域合同

新增 `shieldchain/agents/domain.py` 及单元测试。定义角色、阶段、可信引用、共享事实、假设、风险、预算、共享上下文、角色私有上下文、结构化交接、角色输出与终止原因。类型不可变且防御性冻结；严格校验 UUID、UTC、置信度、owner 和预算；共享事实必须 confirmed 且带引用；不包含 tenant/principal、密钥、原始提示或思维链字段。

## Task 2：租户化案件边界与迁移

为现有事件建立服务端可信 tenant 绑定，新增案件上下文、已确认事实、角色私有上下文、交接和执行记录表。事实、交接、执行摘要的 schema 为只追加仓储准备，数据库层不使用触发器禁止 UPDATE/DELETE，Task 3 由仓储强制只追加并测试；约束、索引和 UTC 边界明确；迁移 upgrade/downgrade/upgrade 且旧仿真数据可读。

## Task 3：上下文仓储与并发修订

建立 tenant-aware 端口和 SQLAlchemy 仓储：创建/读取共享上下文、CAS revision 更新、追加事实、仅访问本角色私有上下文、追加交接/执行并同步现有审计。跨租户、跨案件、跨角色、失效引用和 stale revision 默认失败。

## Task 4：权限、脱敏与注入隔离

实现默认拒绝的访问策略、allowlist 字段投影、权限标签 subset 校验、敏感值脱敏和不可信数据包络。tenant/principal 只由服务端提供；未知内容类型 fail closed；测试权限矩阵、提示注入和日志泄漏。

## Task 5：上下文装配器

实现固定装配顺序、相关性、去重、时间衰减和 Token 预算。先过滤再排序；系统规则和安全边界不可截断；重复内容合并但保留全部来源；超预算显式降级或拒绝；同输入结果稳定。

## Task 6：分层记忆与安全压缩

实现工作/案件/会话/审计/经验记忆边界。压缩必须保留事实引用；原始证据、审批和工具结果引用不可由摘要替代；过期假设退出活动上下文但保留审计；经验只有人工确认且脱敏后才能提交长期知识端口。

## Task 7：结构化交接服务

校验并只追加保存发送方、接收方、结论、引用、置信度、开放问题和建议动作。接收方收到的是 claim，不自动晋升共享事实；引用必须在同租户同案件重新解析；响应角色只产生 proposed action。

## Task 8：专业角色端口与离线实现

每个角色仅接收装配后的上下文并返回严格 Schema。复用现有规则与证据；知识角色直接调用阶段 3 RAG 领域端口；响应角色只规划；验证和报告只读可信事实/审计。LLM 为可插拔端口，默认离线 fake；格式错误、超时和 RAG 拒答显式传播。

## Task 9：超级智能体状态机与安全监督器

实现白名单状态机、确定性监督器和可恢复编排。每步执行、交接和审计原子；预算耗尽、证据不足、冲突、高风险动作或关键依赖不可安全降级时转人工/终止；不得调用未授权工具，不做自由重规划。

## Task 10：只读轨迹、阶段 smoke 与出口门禁

提供只读协作轨迹 API 和最小工作台，只展示共享摘要、角色状态、交接、引用、预算和原因码，不暴露私有上下文、原始提示或思维链。使用临时 SQLite 与离线替身完成阶段 4 smoke；扩展验证脚本、迁移往返、安全评测、文档、路线图和开发日志。

## 快速执行规则

- 同一时间只允许一个实现者修改工作区；只读研究和复审可并行。
- Task 1 只改领域模型；Task 2 才改数据库；Task 4 之前不装配上下文；Task 9 之前不接入编排。
- 每个任务只跑聚焦测试；Task 3、5、8、9 后跑相关跨模块回归；Task 10 才跑完整门禁。
- Critical/Important 问题集中修复一次并复审；每个任务独立提交。
- 不推送、不合并，除非用户明确要求。
