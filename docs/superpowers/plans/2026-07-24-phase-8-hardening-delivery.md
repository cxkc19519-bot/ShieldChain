# 阶段 8：加固与比赛交付实施计划

按 `docs/superpowers/specs/2026-07-24-phase-8-hardening-delivery-design.md` 实施。每个 Task 独立测试和提交；所有默认门禁离线、无费用、无真实设备访问，且不得削弱阶段 2–7 的服务端安全边界。

## Task 1：性能、安全与交付基线

建立固定离线场景、机器可读预算、运行时元数据和基线报告；新增合同确保阈值有单位、样本量和分位数，并建立阶段 8 交付物清单骨架。

## Task 2：HTTP 与生产配置加固

实现安全响应头、Host/CORS 白名单、请求和上传大小/类型限制、公开错误最小化及生产 profile 失败关闭；覆盖代理头、调试开关和敏感配置回归。

## Task 3：数据库、RAG 与聚合性能

审计查询计划、索引、分页上限和重复查询，优化固定事件、知识、工具、ReAct 与报告场景；用稳定分位数预算防止回归。

## Task 4：就绪、版本、日志与关闭

区分 liveness/readiness，提供不泄密的版本投影，统一 request/correlation 日志字段、脱敏和有界关闭；验证迁移落后、配置缺失与关闭中状态。

## Task 5：非 root Docker 与 Compose

新增后端/前端多阶段 Dockerfile、前端静态服务配置、`.dockerignore`、Compose 健康检查、迁移作业和具名数据卷；镜像不包含 secret 或开发产物。

## Task 6：容器 smoke、CI 与供应链合同

新增 Compose 离线 smoke、镜像/用户/健康检查合同、锁文件与依赖审计、离线 CI 工作流；环境缺少 Docker 时明确跳过真实容器执行但仍验证静态合同。

## Task 7：工程与测试文档

完成源代码说明、总体设计、开发说明、测试报告和部署手册；所有命令、指标、限制和文件路径与仓库实际一致。

## Task 8：总结与答辩 PPT

编写项目总结并生成可编辑 PPT，覆盖问题、架构、创新、安全、演示路径、验证数据、局限和路线图；渲染检查文字、图表与 16:9 版式。

## Task 9：三分钟视频

完成 180 秒分镜、旁白、字幕和可重复渲染工程，录制或生成最终 MP4；不得展示凭据、私有字段或虚假真实链路状态。

## Task 10：Phase 8 最终验收与打包

新增 Phase 8 smoke 和交付清单校验，运行完整 Windows/容器可用门禁，记录测试结果、未测边界、提交摘要和比赛提交包内容。

## 快速执行规则

- 每个 Task 独立提交；测试和合同先于实现，失败修复后才进入下一 Task。
- 基线阈值必须宽于稳定本地观测且不可用一次最快结果设定。
- 容器、CI、文档和媒体不得包含 `.env`、Token、真实凭据或开发数据库。
- Docker/浏览器/媒体编码器不可用时保留静态合同和明确未测试状态，不伪造通过。
- 不联网、不产生费用、不调用真实设备，不推送、不合并，除非用户明确要求。
