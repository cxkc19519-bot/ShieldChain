# 阶段 6：受控 ReAct 自主闭环实施计划

按 `docs/superpowers/specs/2026-07-23-phase-6-react-loop-design.md` 实施。每个 Task 独立测试和提交；默认离线，不保存思维链，不提前实现阶段 7 完整前端，不接入真实设备或任意代码执行。

## Task 1：结构化 ReAct 领域合同

定义循环状态、观察引用、失败类别、恢复决策、计划修订、预算快照和人工接管领域对象；强制不可变、UTC、同案件引用、稳定枚举和 JSON-safe 边界。

## Task 2：确定性失败分类器

把阶段 4 角色终态、阶段 5 调用/尝试/验证/控制终态映射为固定失败类别和允许决策；未知组合默认人工复核，不解析原始异常文本。

## Task 3：预算监督与循环检测

实现步骤、循环、时间、Token、费用、工具调用的预计消费检查，以及规范化观察/计划指纹的重复检测；所有超限在新动作前失败关闭。

## Task 4：确定性计划修订器

基于失败类别、当前计划、注册表能力和引用生成严格计划差异；未知变更结果只允许配对查询，拒绝审批/紧急停止/证据冲突不重规划。

## Task 5：持久化模型与可逆迁移

新增循环运行、观察、分类、计划修订和决策表；建立 tenant/case/run 外键、唯一约束、revision/CAS 字段和索引，完成 Alembic 升降升测试。

## Task 6：tenant-bound 仓储与原子提交

实现循环运行 CAS、只追加轨迹、同租户引用校验、原子 step bundle 和跨租户/陈旧 revision 拒绝。

## Task 7：循环执行服务

组合观察、分类、预算、修订和决策，执行一个有界 ReAct step；不直接持有工具适配器，输出只包含 proposed action 或阶段 5 恢复指令。

## Task 8：崩溃恢复与并发控制

扫描过期运行并作出唯一恢复决定；复用阶段 5 租约恢复，确保变更动作未知不重放、多个 worker 不重复提交。

## Task 9：阶段 4/5 编排边界接线

把未验证可信执行交给循环服务；验证成功继续报告，允许的查询/重规划返回受控执行边界，其余转人工。保持响应角色和工具网关隔离。

## Task 10：只读循环轨迹与人工接管 API

提供服务端 tenant-bound 轨迹和接管/恢复端点，严格 Schema 与安全投影；覆盖越权、额外字段、原始结果/提示/思维链泄漏测试。

## Task 11：阶段 6 离线 smoke

使用临时 SQLite 覆盖验证失败→观察→分类→计划修订→新 proposed action→可信工具→验证成功，以及未知结果查询、循环检测、预算耗尽、审批拒绝和人工接管。

## Task 12：出口门禁与文档

扩展 `verify.ps1`、脚本合同、迁移往返和安全扫描；更新架构、README、路线图和开发日志，运行完整后端/前端门禁并独立提交。

## 快速执行规则

- 同一时间只有一个实现者修改工作区；每个 Task 独立提交。
- Task 5 前不接数据库，Task 7 前不执行循环，Task 9 前不改编排器，Task 10 前不开放 API。
- 每个 Task 跑聚焦测试；Task 4、6、9 后跑跨模块回归；Task 12 才跑完整门禁。
- 默认清除所有 live 开关，不联网、不产生费用、不执行 Shell、不操作真实设备。
- 不推送、不合并，除非用户明确要求。
