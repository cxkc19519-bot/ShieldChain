# 告警误报治理最小闭环

## 已实现流程

1. Wazuh 高风险告警进入只读人工复核队列，接收告警本身不会启动模型或处置。
2. 操作员显式启动案件调查，现有多智能体团队运行；告警页面读取并展示“告警分诊智能体”的公开摘要、工具选择原因和模型名称。
3. 只有存在案件级调查运行后，分析员才能追加人工定性：确认误报、确认有效告警或证据不足。
4. 确认误报时可选择不抑制、同规则同终端抑制建议或同规则全局抑制建议。建议必须带到期时间，后端限制最长 90 天。
5. 每次定性追加写入，案件展示最近结论；统计按每个案件的最近结论计算已定性数、误报数、有效告警数、证据不足数、误报率和抑制建议数。

## 安全边界

- 智能体不能直接把告警定为误报；它只提供供分析员核对的证据摘要。
- 人工定性不会删除或覆盖原始 Wazuh 告警。
- 抑制记录只是建议，不会修改 Wazuh 规则，也不会静默未来告警。
- 结论原因受服务端白名单校验：误报、有效告警和证据不足各自只能使用相符原因。
- 未完成智能体调查的案件不能定性；抑制建议必须属于确认误报，且必须设置未来 90 天以内的到期时间。

## 尚未完成

- Wazuh 规则发布、版本管理、双人审批、到期自动撤销和回滚连接器；
- 按规则、资产、分析员和时间趋势的多维统计；
- 把人工反馈转为候选阈值或白名单后，在正常流量与攻击留出集上自动回归；
- 生产 RBAC、真实分析员身份、工单关联和长期误报率验收。

因此本阶段可以称为“可审计的误报治理最小闭环”，不能称为“全自动误报剔除”。
