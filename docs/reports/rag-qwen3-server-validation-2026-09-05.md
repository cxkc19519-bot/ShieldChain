## 1. 结论

原版 Qwen3-30B-A3B 已完成模型直连、智能助手、RAG、多智能体、工具选择、安全规划和历史报告检索的真实链路验证。RAG 与智能助手质量门禁均通过，7 个专业智能体均由真实模型完成调用，没有触发保守降级，也没有执行任何处置动作。

本次验证使用独立 Milvus collection、独立状态文件和独立验证目录，不向生产知识库写入测试文档，不触碰 Qwen3.8 模型。

## 3. 本次修复

1. 嵌入请求按每批 64 条分批发送，避免大文档一次提交超过嵌入服务上限，并确保索引失败时不会错误标记为成功。
2. 语义分块结果过长时进行确定性拆分，不再因为单个超长分组放弃整篇文档的语义规划。
3. 查询改写结果在去重后按配置数量截断，避免模型返回了有效扩展词却因数量略多而被整体降级。
4. 调整混合召回、标题相关性、重排门槛和文档多样性逻辑，兼顾召回率与主要证据的精确引用。
5. 智能助手只使用最终引用所对应的 RAG 分块生成回答，避免回答上下文与显示引用不一致。
6. 修复 Linux 符号链接清理、UTC 日期边界及 Qwen 测试替身参数兼容问题。

## 7. 限制与后续建议

- 本轮重点是功能正确性与质量门禁，不等同于生产并发、长时间稳定性和容量压测。
- BGE-M3 与 reranker 当前使用 CPU，单次 RAG P95 约 20.59 秒；若比赛演示要求更低延迟，应考虑 GPU 化或缓存。
- 少数大型 PDF 仍会回退到规则分块，但向量完整写入，不再造成文档缺失。
- Bing 搜索依赖外部网络和搜索服务可用性，生产环境需要超时、配额和降级监控。
- 生产知识库内容仍由实际导入决定；本报告的测试文档没有写入生产 collection。
