## 2. v3 新增能力

在 v2 的 23 条规则基础上新增 14 条规则，总计 37 条，新增覆盖：

- ASP/PHP 的 `eval`、`Response.Write`、`base64_decode` WebShell 模式；
- reDuh 的 `createSocket`、`getData` HTTP 隧道控制动作；
- PowerShell 编码执行和向 PHP 端点提交 PowerShell 载荷；
- Unix 交互 Shell 命令；
- 蚁剑 Electron 客户端特征；
- Xnonymoux PHP WebShell；
- 截断 TCP 流中的重复 ASP `Response.Write` 载荷。

Zeek 行为逻辑新增：

- 同一服务端脚本端点至少 3 次、请求体不小于 2 KB 的重复 POST；
- 同一脚本端点至少 8 次 POST 且出现较大命令响应；
- HTTP 行为后出现 1337、4444、5555、6666、7777、9001 等端口上的长连接；
- 隧道、PowerShell、反弹连接的中文分类与 ATT&CK 映射。

## 5. 标签事后核验

只有在验证运行完成、结果数字锁定后才查看本批标签。

24 个样本中有 10 个文件名包含可读攻击说明：

- 发现或分类基本正确：Struts2-029、GSL PHP WebShell、MSSQL 写入 WebShell、菜刀 ASPX、Log4j Shell；
- 已发现但分类偏低：MSSQL `sp_makewebtask` 写入 WebShell被标为扫描；
- 未发现：Response Command、MySQL duplicate-column 报错探测、菜刀 JSPX、JSP File Browser 大马。

因此，可读标签样本的广义发现覆盖为 6/10，语义分类基本正确为 5/10。该数字仍不是生产准确率。

## 6. 重要限制

- 当前缺少经过确认的正常企业流量，无法计算误报率、精确率和特异度。
- 加密流量、截断 PCAP、未知协议和仅存在于终端侧的行为可能无法被网络探针发现。
- 开发集的 23/23 结果包含规则调试过程，不能对外宣称为泛化能力。
- SQL 注入规则在单个验证样本中产生大量重复告警，需要在正常流量集上评估和聚合。
- 最终 935 个盲测样本仍保持封存。

## 7. 下一步

1. 为 Response Command、菜刀 JSPX/JSP 文件浏览器和 MySQL 报错探测寻找开发集同族样本；

4. 完善 Wazuh 终端规则，关联 Web 目录写入、服务进程启动命令和异常外联；
5. 规则与评估协议最终冻结后，再运行 935 个最终盲测样本。
