# ShieldChain

ShieldChain 是面向安全运营场景的多智能体分析系统。系统接收 Wazuh 等安全平台转发的真实告警，结合本地知识库、历史调查报告和受授权的只读工具，由专业智能体完成检索、研判、协作和安全运营报告生成。

项目默认坚持“分析与处置分离”：模型可以规划、选择工具和生成建议，但不能绕过确定性安全规则、审批、可信工具网关和执行后验证边界。

## 先用 3 分钟看懂项目

如果你第一次接触 ShieldChain，可以先记住下面五点：

1. **数据从哪里来**：目前主要接收 Wazuh 转发的真实安全告警，也可以导入公开或脱敏数据进行测试。
2. **智能体做什么**：智能体负责查询、分析、补充知识、规划建议和生成报告，不直接获得系统管理员权限。
3. **为什么需要 RAG**：大模型本身不知道项目里的历史事件，也不应凭记忆回答法规和安全知识，因此需要检索本地知识库和历史报告。
4. **为什么还有服务端规则**：模型负责判断“下一步查什么”，服务端负责限制“它最多能查什么、参数是否合法、结果能否执行”。
5. **最终谁负责决定**：当前系统输出的是研判依据和建议，真实封禁、隔离、修复仍由人审批。

ShieldChain 可以理解成位于 Wazuh/XDR 与安全运营人员之间的“智能分析层”：

- 它不是杀毒软件，也不是网络探针；
- 它不替代 Wazuh、Zeek、Suricata 或商业 XDR 的数据采集；
- 它把这些系统产生的数据组织起来，让多个专业角色协作研判；
- 它把知识库、历史经验和当前证据汇总成更容易复核的结果。

## 当前完成度与适用边界

当前版本是可运行的比赛/科研原型，不是可以直接替代企业 SOC/XDR 的生产平台。

**已经可以演示和验证：**

- 真实 Wazuh 告警接入、持久化和前端展示；
- 7 个角色的受控 ReAct 多智能体协作；
- 事件、告警、漏洞、弱口令四类只读工具；
- 文档持久化、分块、向量检索、混合检索和重排；
- 历史调查报告自动进入知识库；
- 安全运营报告生成与 HTML 预览；
- 持久化智能助手和独立模型测试页面；
- DeepSeek API 与本地 Qwen/vLLM 两种推理模式。

**仍需生产化完善：**

- 资产台账、身份系统、工单系统和更多真实数据源；
- 跨数据源事件关联、误报治理和攻击链还原；
- 完整 RBAC、租户隔离、密钥托管、监控和高可用；
- 真实处置动作的审批、回滚、幂等和执行后验证；
- 长期真实数据集上的效果评估。

## 主要功能

- **真实告警接入**：接收、持久化并展示 Wazuh 高风险告警，支持人工复核和关联分析。
- **安全多智能体协作**：专业角色通过 ReAct 循环自主观察、选择工具、分析结果和交接任务。
- **安全运营报告智能体**：校验时间参数，自主选择事件、告警、漏洞、弱密码四类只读 MCP 工具，以通用运行 ID 关联任务，并生成结构化建议、Markdown 和 HTML 预览；旧报告明确标记无运行记录。
- **RAG 知识库**：支持文档持久化、语义分块、混合检索、向量检索、重排、版本管理和分块查看。
- **智能助手**：结合知识库与历史调查报告回答问题，对话和本地记忆持久化保存。
- **本地模型部署**：提供 vLLM OpenAI 兼容服务配置，可使用 `Qwen3-30B-A3B-Instruct-2507-FP8` 替代外部 DeepSeek API。
- **安全边界**：只向前端公开受控轨迹和可验证结论，不公开私有提示词、思维链、原始凭据或敏感工具结果。

系统分为四层：

- **数据层**：保存告警、事件、报告、知识库、对话历史和审计信息；
- **工具层**：向智能体暴露经过白名单限制的只读查询能力；
- **智能体层**：由总控和专业角色完成规划、观察、工具调用和交接；
- **展示与控制层**：前端显示结果，由人决定是否进入真实处置。

## 一次安全分析如何完成

以“一段时间内出现多个高风险告警”为例：

1. Wazuh 将达到阈值的告警发送到 ShieldChain；
2. 后端校验 Webhook Token、时间字段、严重等级和幂等键；
3. 告警写入 SQLite，并形成待人工复核事件；
4. 用户在安全运营报告页面选择时间范围并启动任务；
5. 总控智能体查看公开状态，选择下一位专业智能体；
6. 专业智能体根据职责和工具说明决定是否调用工具；
7. 角色只公开摘要、观察和交接理由，不公开私有思维链；
8. 报告综合环节区分已确认事实、工具线索、知识依据和未知项；
9. 系统生成中文报告、Markdown 和 HTML 预览；
10. 安全人员复核后，再决定是否封禁、隔离、修复或继续取证。

### ReAct 在本项目中的含义

每个专业角色在有限轮次内执行“观察—行动—再观察”：

1. 阅读职责、前序交接和当前观察；
2. 阅读获授权工具的用途、适用场景、禁用场景和证据限制；
3. 调用一个工具，或者在证据已经足够时结束；
4. 获取服务端返回的受控观察；
5. 再判断是否需要其他工具；
6. 输出不含私有推理的公开中文摘要。

模型不能无限循环，也不能选择角色白名单之外的工具。同一工具在一次角色运行中只执行一次，后续读取缓存结果。

## 智能体团队

ShieldChain 当前启用 7 个专业智能体。它们不是按固定顺序依次运行：总控智能体通过 ReAct 循环观察当前公开状态，再根据任务、证据缺口、剩余预算和可用工具选择下一位专业智能体。

| 智能体 | 主要作用 | 典型输出 |
| --- | --- | --- |
| **总控智能体** | 理解任务目标和当前事实，选择下一位专业智能体，管理交接、循环预算和结束条件。 | 选择原因、当前风险焦点、交接摘要。 |
| **告警分诊智能体** | 对事件和告警进行分级、去重和优先级排序，识别需要优先人工处理的对象。 | 告警优先级、分诊依据、待处理清单。 |
| **威胁研判智能体** | 关联告警、漏洞、资产和攻击迹象，区分已确认事实、可疑线索与仍需补证的判断。 | 风险判断、攻击线索、证据缺口。 |
| **知识检索智能体** | 在需要外部依据时自主调用 RAG，检索行业规范、ATT&CK 技战术、漏洞知识和处置手册。 | 带来源的知识摘要、相关依据。 |
| **响应规划智能体** | 根据风险和证据生成严格、版本化的响应建议；运营报告当前只允许零动作计划并明确标注未执行，不直接执行高风险动作。 | 计划 ID、处置建议、前置条件、风险提示。 |
| **验证智能体** | 定义建议实施后应重新检查的日志、指标、资产状态和验收条件，不把“建议验证”写成“已经验证”。 | 验证清单、成功条件、失败判据。 |
| **报告智能体** | 汇总已确认事实、证据局限、风险结论、建议和引用，形成面向人工复核的中文报告。 | 调查摘要、研判结论、运营报告。 |

### 安全运营报告智能体

安全运营报告智能体是上述团队的任务入口和结果呈现层，负责：

1. 生成并校验查询时间范围；
2. 根据任务自主选择事件、告警、漏洞、弱密码四类只读 MCP 工具，不要求每次全部调用；
3. 分析工具返回结果，并将受控观察交给 ReAct 智能体团队；
4. 综合多角色结论，输出建议和限制条件；
5. 完成中文排版，并生成 Markdown 与 HTML 预览。

模型可以选择角色和只读工具，但角色白名单、工具权限、参数模式、调用预算、停止条件和输出校验均由服务端控制。模型、RAG 或工具不可用时，系统保留已经确认的事实，明确标注缺口并转人工处理，不会伪造工具结果、处置完成或验证成功。

### 推荐使用顺序

第一次体验时建议按以下顺序操作：

1. 在“运营总览”确认控制面正常；
2. 在“实时告警”确认 Wazuh 或离线 NTA 告警已经入库；
3. 在“安全运营报告”选择覆盖告警时间的范围并生成报告；
4. 查看多智能体协作、只读 MCP 调用和报告预览；
5. 在“历史报告”查看调查详情、审计记录和受控操作入口；
6. 在“知识库”上传安全政策或 ATT&CK 文档并确认分块、索引和混合检索；
7. 使用“智能助手”验证知识库和历史报告问答；
8. 最后使用“模型测试”单独判断 Qwen 基础能力，避免把模型问题与 RAG 问题混淆。

### 容易混淆的页面

- **安全运营报告 vs. 历史报告**：前者按时间窗口分析多源运营数据并生成新报告；后者保存调查运行记录，并提供详情、审计和处置入口。
- **智能助手 vs. 模型测试**：前者有本地会话、记忆、知识库和历史报告检索；后者主要用于直接验证基础模型。
- **智能体工作台 vs. 隐藏思维链**：页面只展示允许公开的角色决策、工具选择和交接结果，不展示模型私有思维链。
- **实时告警 vs. 已确认事件**：实时告警是待复核线索，必须结合端点、时间、规则、网络和资产证据研判。
- **服务状态 vs. 真实监控**：当前服务状态页是静态展示；运营总览和服务器健康接口才反映实际可用性。

### 智能助手可以怎么用

智能助手不是按照预设按钮机械回复的客服机器人。用户可以用自然语言连续追问，并让它结合已有材料完成安全分析。例如：

- 询问“什么是横向移动”“钓鱼邮件通常有哪些行为特征”等安全知识；
- 查询“最近一次高风险调查的研判结论是什么”，定位并归纳历史调查报告；
- 比较多份历史报告中的攻击入口、受影响资产、证据缺口和处置建议；
- 上传监管政策、ATT&CK、漏洞分析或内部制度后，让助手总结文档、提取检查项、生成整改清单；
- 根据指定文档整理安全分析报告、汇报提纲或初稿，并通过后续对话调整结构和措辞；
- 在本地资料不足时，明确要求它使用获授权的公开搜索补充背景，再区分“项目内证据”和“公开资料”。

智能助手的回答可以作为分析和写作辅助，但不等同于已经确认的事件事实或正式审批结论。正式的时间窗口统计、多智能体工具调用记录、HTML/Markdown 运营报告和可审计结果，应使用“安全运营报告”页面生成。

### 智能体工具说明

模型收到的不只是工具名称，还会看到 description、use_when、do_not_use_when、parameters、returns 和 limitations。

| 工具 | 用途 | 证据限制 |
| --- | --- | --- |
| security.events.list | 查询由告警归并形成的待复核事件。 | 不代表威胁已经确认。 |
| security.alerts.list | 查询 Wazuh 规则、等级和告警标题。 | 可能误报、重复或缺少上下文。 |
| security.vulnerabilities.list | 从告警中提取 CVE 和关联线索。 | 出现 CVE 不等于资产确定受影响。 |
| security.weak_passwords.list | 筛选密码喷洒、暴力破解等认证风险。 | 不读取密码，也不能直接确认弱口令。 |
| knowledge.rag.retrieve | 检索知识库和历史调查报告。 | 知识不能证明当前事件事实。 |

### DeepSeek 和本地 Qwen 为什么使用同一组变量

项目使用统一的 OpenAI 兼容客户端。DEEPSEEK_BASE_URL、DEEPSEEK_MODEL 和 DEEPSEEK_API_KEY 是早期沿用的变量名，既可以连接 DeepSeek，也可以连接本地 vLLM/Qwen。

本地 Qwen 覆盖配置会自动使用：

~~~dotenv
DEEPSEEK_BASE_URL=http://local-llm:8000/v1
DEEPSEEK_MODEL=shieldchain-qwen3-30b
DEEPSEEK_API_KEY=local-vllm
~~~

其中 local-vllm 是本地兼容接口的占位鉴权值，不是 DeepSeek 密钥。

## 学校服务器：同门登录与一键启动

学校服务器的 IP、端口和账号由项目负责人通过私密渠道发送给获授权成员，不写入公开仓库。当前实例的 ShieldChain 运行目录固定为 `/home/user/jhk/shieldchain`。服务器没有桌面环境，前端在服务器运行，通过 SSH 隧道显示在同门自己的浏览器中。

### 1. 登录前的准备

每位同门需要准备：

- 已连接学校内网或校园 VPN；
- 已获得服务器管理员和账号负责人的访问授权；
- 自己的 SSH 私钥，且对应公钥已经加入服务器的 `/home/user/jhk/.ssh/authorized_keys`；
- Windows 自带的 OpenSSH，或者其他可信 SSH 客户端。

不要在群聊、网盘或仓库中共享 `jhk` 的密码和任何人的私钥。多人共用同一个 Linux 账号会共享文件权限、Shell 历史和操作责任，比赛期间可以临时协作，长期使用建议让学校管理员为每位成员创建独立账号，再通过用户组共享项目目录。

### 2. 从本机建立 SSH 隧道

在同门自己的 Windows PowerShell 中执行，把 `<自己的私钥路径>` 换成实际路径：

```powershell
ssh -i "<自己的私钥路径>" -p <SSH端口> `
  -L 8080:127.0.0.1:8080 `
  <获授权账号>@<服务器IP>
```

如果已经在 `C:\Users\用户名\.ssh\config` 配置了自己的服务器别名，也可以直接执行：

```powershell
ssh -L 8080:127.0.0.1:8080 <自己的SSH别名>
```

该终端必须保持打开。隧道只把服务器本机的 ShieldChain 前端映射到本机，不会把服务公开到校园网或互联网。

也可以在本地仓库使用 Windows 一键连接脚本。服务器 IP 仍通过私密渠道填写，私钥只从同门自己的电脑读取：

```powershell
.\scripts\server\connect_shieldchain.ps1 `
  -ServerHost "<服务器IP>" `
  -Port <SSH端口> `
  -UserName "<获授权账号>" `
  -IdentityFile "<自己的私钥路径>"
```

该脚本会建立 `8080` 端口隧道、登录服务器、调用服务器启动脚本，并保留远程终端。它不会上传、复制或记录私钥。

### 3. 在服务器一键启动

登录成功后执行：

```bash
cd /home/user/jhk/shieldchain
./scripts/server/start_shieldchain.sh start
```

脚本默认使用：

- `compose.yaml`：基础服务；

### 4. 启动失败时先检查

```bash
./scripts/server/start_shieldchain.sh status
docker ps -a
nvidia-smi
```

常见原因包括：校园 VPN 未连接、SSH 密钥未授权、共享 GPU 正被其他任务占用、Qwen 权重不完整、Docker 镜像尚未下载或 `.env` 缺失。服务器是共享设备，不得终止、修改或抢占其他用户的进程；GPU 忙时应先和实验室同学协调。

### 当前不足与结论边界

- 当前持久化知识库还是空的，尚未正式导入行业监管政策、ATT&CK、漏洞研究、内部制度等高质量材料。智能助手虽然可以自然对话和检索历史报告，但在知识库为空时不能提供项目文档引用，也无法验证完整的知识库 RAG 效果。比赛前需要完成文档筛选、上传、分块检查、索引构建和检索验收。
- PCAP 是比赛方提供的真实/脱敏流量，Zeek 和 Suricata 也确实参与分析；但当前事件类别、严重程度和部分 ATT&CK 编号仍主要通过文件名关键词映射，不能声称完全由检测规则独立识别。
- 文件名标签是数据集真值，只适用于离线测评；不能把它包装成生产环境中的模型发现结果。
- 当前服务器没有接入交换机 SPAN/TAP 镜像流量，因此 Zeek/Suricata 不是全天候网络探针，只是安全隔离的离线分析器。
- Wazuh + OpenSearch + ShieldChain 能覆盖采集、规则告警、检索和智能分析，但还不具备商业 XDR 完整的资产治理、检测内容库、跨设备关联和生产自动响应能力。
- 漏洞和弱密码 MCP 当前仍可能缺少真实扫描器数据源；没有真实数据时，报告必须显示“无数据”或“依据不足”，不能由模型补写。
- 自动封禁、终端隔离和账号停用仍受人工审批与可信工具网关约束，当前结果用于研判和比赛演示，不应直接作为生产处置指令。

后续应优先把分类逻辑升级为“Suricata 告警规则 + Zeek 行为特征 + Wazuh 主机证据”的联合检测，并在获得授权的 SPAN/TAP 环境完成实时探针验收。

### 为什么当前还不能直接用于真实流量生产环境

当前项目已经能处理比赛方提供的真实/脱敏 PCAP，也能接收 Wazuh 告警并由多智能体完成研判和报告生成，但这与“持续检测真实网络流量的生产系统”仍有明显差距：

- 没有交换机 SPAN、网络 TAP 或云流量镜像输入，Zeek/Suricata 目前只离线读取 PCAP，并未持续监听实际业务链路；
- 离线数据集的事件类别、严重程度和部分 ATT&CK 映射仍借助文件名真值，不能等同于未知流量中的独立发现；
- 还没有常驻的流量采集、解析、标准化、去重、关联、重试和积压恢复链路；
- Wazuh 主机告警与 Zeek/Suricata 网络证据尚未形成成熟的资产、账号、进程、域名和会话级关联；
- 漏洞、弱密码工具可能没有接入真实扫描器，因此部分报告只能正确显示“无数据”或“依据不足”；
- 尚未完成吞吐量、丢包率、端到端延迟、误报率、漏报率、峰值积压和长时间稳定性测试；
- 当前以单套比赛环境为主，未完成高可用、灾备、权限审计、证书管理、备份恢复和故障演练；
- 自动封禁、隔离终端、停用账号等动作仍需人工审批和可信工具网关保护，不应直接用于生产处置。

因此，当前准确的表述是：**已跑通真实/脱敏离线流量、主机告警接入、开源探针分析和多智能体研判闭环，具备向实时检测演进的基础；尚未完成生产级实时流量验收。**

### 从当前版本走向真实流量应用

建议按以下顺序推进，每一步验收通过后再扩大范围：

1. **确认合法流量入口**：由学校网络中心或实验室明确测试网段、数据边界和授权，提供 SPAN/TAP、虚拟交换机镜像或云流量镜像；不得私自监听无授权网络。
2. **部署常驻网络探针**：将 Zeek 和 Suricata 部署在能够接收镜像流量的独立传感器上，固定接口、时间同步、规则版本和日志目录，并验证重启后自动恢复。
3. **建立持续入库链路**：把 Zeek、Suricata、Wazuh 输出统一为 ShieldChain 事件模型，补齐资产、用户、进程、五元组、规则、置信度和原始证据引用，增加消息队列、幂等、重试、死信和积压监控。
4. **完成联合检测**：以 Suricata 规则告警为触发，以 Zeek 行为元数据和 Wazuh 主机证据交叉验证，减少仅凭单一规则或文件名标签得出结论的情况。
5. **建立基线并调优**：先在隔离测试网运行观察模式，统计正常业务基线、误报和漏报；对规则白名单、阈值、资产重要度和 ATT&CK 映射做版本化管理。
6. **开展受控攻防验证**：在靶场或获授权测试环境中回放恶意 PCAP、运行 Atomic Red Team/自建测试用例，逐项核对“流量—告警—事件—调查—报告—处置建议”的证据链。
7. **完成容量验收**：记录峰值带宽、每秒事件数、丢包率、检测延迟、查询延迟、模型并发、GPU/CPU/内存/磁盘水位和数据保留周期，形成可复现的测试报告。
8. **最后开放受控处置**：先只给建议，再开放需要人工确认的动作；只有在权限、审批、回滚、超时、重复执行保护和完整审计都验证后，才考虑有限自动化。

### 比赛展示时如何准确说明

现有比赛材料主要说明平台部署、开放接口、MCP、自建智能体框架和数据集申请方式，没有明确写出参赛作品必须持续接入现场实时镜像流量。技术答疑还建议对可能产生误封风险的阻断/响应 API 采用模拟方式展示。因此，在赛事方进一步确认前，推荐准备两层演示：

- **可稳定复现的主展示**：使用比赛方真实/脱敏 PCAP 与 Wazuh 告警，展示 Zeek/Suricata/Wazuh、标准化入库、多智能体研判、报告和受控处置闭环；
- **实时能力证明**：若能取得授权镜像端口，在隔离测试网增加小规模实时流量演示，并展示吞吐量、延迟、丢包率和误报统计。

可以表述“开源 XDR/探针替代链路已跑通并支持真实数据验证”，不要表述为“已经完整替代商业 XDR”或“已经达到生产级实时检测”。赛前应向赛事方书面确认是否要求实时流量、是否必须使用深信服组件，以及验收指标和网络授权方式。

## 深信服 AI 安全平台如何访问

根据比赛方提供的部署说明、技术答疑和使用手册，深信服 AI 安全平台不是一个面向参赛队直接注册的公共 SaaS 网页。文档描述的是：先在学校或指定环境部署平台并完成授权激活，再用该部署环境的 IP 或域名通过浏览器登录。提供的材料没有给出统一的公网登录地址、默认账号或默认密码。

### 申请与开通条件

1. 学校或团队先准备满足要求的 XDR、GPU 算力和探针环境，并提供环境信息供深信服评估；
2. 向 `daitingting@sangfor.com.cn` 发送申请，邮件主题为 `【AI安全运营测试项目测试申请】院校名+作品名称+团队名称`；
3. 邮件中提供学校和团队信息、指导教师/联系人、200～300 字作品构思、盖章报名表，以及学校可提供的 XDR、GPU、探针环境信息；
4. 申请通过后，深信服提供对应安装资料、技术文档和软件授权支持；
5. 平台部署并激活授权后，才能在平台内取得 API Key，或进一步申请配套脱敏数据集和接口权限；
6. 技术答疑明确说明：申请脱敏数据集和安全 GPT 接口权限时，需要发送已部署设备 ID 与参赛队信息。

比赛方部署说明给出的参考资源较高：分布式 XDR 虚拟机建议不少于 32 核 CPU、256 GB 内存、240 GB SSD 系统盘和 5 TB 数据盘；AI 算力服务器示例为双路服务器、512 GB 内存和 4 张 RTX 4090D；探针参考为 4 核、4 GB 内存、64 GB 系统盘、128 GB 数据盘，网络吞吐 500 Mbps、应用层吞吐不超过 250 Mbps。最终仍以深信服根据设备评估后提供的版本和授权为准。

### 登录、模型和网络前提

- 平台部署后，由管理员提供实际访问 IP/域名和账号；文档中的“登录平台”均指这个已部署实例；
- 平台需要能够连通所配置的大模型接口，XDR 运营平台还需要正确解析 DNS；
- OpenClaw 初始化需要配置模型 API，企业微信/飞书属于可选项，使用时需配置相应凭据和用户白名单；
- 调用外部 MCP、Hook、模型或知识服务时，相关域名/IP 需要加入外联白名单；
- 技术答疑称安全垂直模型接口由平台内部调用，不等同于给任意外部系统发放一个公共模型 API；
- FastGPT/OpenClaw 中发布的单个智能体可以生成访问地址或 API，但这是平台部署完成后的作品入口，不是平台管理端的公共入口。

### XDR OpenAPI 如何认证

比赛物料中的 XDR OpenAPI 说明使用 Access Key/Security Key 签名认证，并提供作用等价的“联动码 `authCode`”。基本流程是：

1. 登录已经部署的 XDR，从浏览器地址栏确认平台 `host`；
2. 在“配置管理 → 系统设置 → 开放性 → 联动码管理”获取联动码；
3. 从接口开放列表选择 API，将 `auth_code`、`host`、`url` 和请求参数交给 SDK 计算签名；
4. 签名后直接发送请求，不能再修改 URL、参数、请求体或请求头，否则必须重新构造并签名。

这意味着仅下载 XDR/GPT 软件包或 OpenAPI 示例，并不会自动获得可用的平台地址、授权、联动码或数据权限。若团队继续采用 Wazuh、Zeek、Suricata 和本地 Qwen 的开源路线，可以独立完成作品，但不能宣称已经接入深信服官方 AI 安全平台或取得其官方数据/接口授权。

## 常见问题

### 不调用 LLM 还算智能体吗？

如果只有固定状态机和规则判断，更接近自动化工作流。ShieldChain 的 ReAct 角色会调用模型观察上下文并自主选择获授权工具，服务端规则负责权限和安全边界。

### 为什么显示“保守降级”？

表示模型、RAG 或工具不可用，系统只保留已确认事实并转人工。降级不代表 LLM 调用成功，也不代表处置完成。

### 为什么智能助手有时不直接回答？

安全知识问题需要知识库或历史报告依据。检索不到时助手会说明资料不足，避免编造。普通寒暄不需要 RAG，会由模型自然回复。

### 为什么模型测试能回答，智能助手却说资料不足？

模型测试直接体验基础模型；智能助手必须遵守知识依据约束。模型“知道一些东西”不等于项目知识库已经提供了可追溯证据。

### 知识库关机后还在吗？

只要使用相同持久化目录或 Docker 数据卷，并且没有执行 down -v 或主动删除，知识库、报告和助手对话都会保留。

### 可以直接用于生产封禁吗？

不建议。当前重点是分析、检索、报告和人工复核。生产处置还需要企业审批、IAM、工单、回滚和审计。

### 服务器没有桌面环境，怎么打开前端？

通过 SSH 端口转发把服务器的 127.0.0.1:8080 映射到本机，再用本机浏览器访问。

### 没有交换机镜像流量还能演示吗？

可以使用 Wazuh 终端告警、公开/脱敏数据集和受控测试数据。没有 SPAN/TAP 时不能声称已经采集整个网络的真实镜像流量。

## 安全说明

- 不要提交 `.env`、`backend/data/`、模型权重、数据库、API Key、密码或真实客户数据。
- 默认工具为只读查询；任何真实处置动作都必须经过策略、审批、可信工具网关和结果验证。
- 历史报告和知识库可包含敏感安全信息，部署时应限制网络暴露、访问权限和备份范围。
