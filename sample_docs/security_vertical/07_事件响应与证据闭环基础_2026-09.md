# 事件响应与证据闭环基础（2026-09）

> 版本：2026.09.0｜最后核验：2026-09-09｜下次复核不晚于：2026-10-02｜复核角色：事件响应知识库管理员｜资料属性：内部安全知识库。本文用于调查、遏制、恢复和复盘，不构成对生产系统执行操作的授权。

## 1. 闭环不是“发出命令”

完整事件响应需要准备、发现、分析、响应、恢复和改进贯穿风险管理活动。一次工具调用成功只证明接口返回成功；闭环还需要确认目标状态发生预期变化、危害没有继续扩大、业务能够恢复、证据和决策可以审计。

NIST SP 800-61 Rev.3 将事件响应纳入 CSF 2.0 的整体风险管理：https://csrc.nist.gov/pubs/sp/800/61/r3/final

NIST CSF 2.0 以 Govern、Identify、Protect、Detect、Respond、Recover 六类功能组织网络安全成果：https://www.nist.gov/cyberframework

## 2. 事实、推断和未知项

事实来自可追溯的日志、流量、资产、身份、执行回执和状态查询。推断必须说明依赖哪些事实及替代解释。未知项应明确写出缺失的数据和最小验证动作。告警规则标题、威胁情报标签或模型判断都不能独立证明漏洞利用成功、代码执行、横向移动或数据泄露。

## 3. 调查时间线

时间线至少包含事件时间、接收时间、分析时间和动作时间，并标明时区、时钟来源及偏差。关联顺序应是：观察到什么 → 哪些实体相关 → 由谁或哪个角色得出何种公开结论 → 依据什么策略作出决定 → 调用了什么受控工具 → 返回什么回执 → 如何独立验证。

不要记录模型隐藏思维文本。应记录可审计的事实、证据引用、公开推断、置信度、替代解释、决策理由和工具结果。

## 4. 遏制、根除与恢复

遏制用于限制危害，例如短期封禁来源、隔离端点、撤销会话或限制账号。根除针对根因，例如移除恶意持久化、修复漏洞、轮换受影响凭据。恢复包括业务验证、监控增强和逐步解除临时控制。三者不可混为一个“已处置”状态。

高影响动作应有明确目标、允许范围、期限、幂等键、失败停止条件、回滚方案和验证器。验证应尽量通过独立只读查询完成；超时不能直接重放有副作用的动作，应先查询当前状态。

## 5. 关闭标准

案件关闭至少满足：调查范围已说明；关键证据可追溯；已知与未知明确；处置动作有回执；目标状态验证通过；业务影响经过确认；临时控制有到期或交接安排；失败与重规划被记录；报告和原始证据按保留策略保存。

如果证据仅能证明“攻击尝试”，报告必须保持这一边界。没有端点或应用侧证据时，不能从网络请求直接推导为代码执行成功；没有身份和目标资产证据时，不能声称发生横向移动。

## 6. 复盘与反馈

复盘不以追责为目的，而是更新检测规则、数据覆盖、资产信息、响应手册和授权策略。需要量化从发生到检测、从检测到研判、从决策到执行、从执行到验证的耗时，并单独记录模型、工具和数据源失败。
