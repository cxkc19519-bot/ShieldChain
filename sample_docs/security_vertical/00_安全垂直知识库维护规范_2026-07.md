# 安全垂直知识库维护规范（2026-07）

> 知识包版本：2026.09.3｜最后核验：2026-09-02｜复核角色：知识库管理员｜下次复核不晚于：2026-10-02｜资料属性：内部安全知识库。知识包导入前必须通过 `manifest.json` 的来源、复核窗口和 SHA-256 完整性校验。

## 目标与适用范围

本知识库服务于 ShieldChain 的安全调查、知识问答、告警研判和人工处置辅助。内容覆盖中国网络与数据安全合规、0day/在野利用漏洞响应、MITRE ATT&CK 企业技战术，以及深信服官方安全研究与运营方法。它不是法律意见、漏洞利用指南或自动化处置授权。

## 官方来源分级

- `primary_authority`：法规发布机关、漏洞/在野利用目录维护机构、框架或标准的原始发布者，例如中央网信办、CISA 和 MITRE。涉及条款原文、CVE 状态、KEV 状态和 ATT&CK 对象时必须优先引用这一层。
- `official_vendor`：安全厂商自有 PSIRT、规则库、研究实验室和正式报告。深信服千里目安全技术中心、产品安全中心与技术支持站属于这一层；可用于趋势、检测和运营实践，但其引用的法规、CVE 或第三方事件仍应回到一级权威事实源交叉核验。
- 新闻、自媒体、搜索摘要和未署名转载不能进入受管知识包；只能作为待核验线索。

## 内容质量门槛

1. 法规、监管文件仅使用中国政府网、中央网信办、主管部门或正式标准发布页。
2. 漏洞情报优先使用厂商安全公告、CISA KEV、CVE/NVD、CERT；新闻只作线索，不能作为唯一事实来源。
3. ATT&CK 技战术以 MITRE ATT&CK 官方版本和官方 STIX/CTI 数据为准。
4. 每个文档必须标出版本、最后核验日期、适用范围、来源 URL、可执行控制点与失效条件。
5. 不收录真实凭据、可直接用于入侵的 exploit、未公开漏洞细节、个人信息或未经授权的内部日志。
6. 每条来源必须使用 HTTPS 权威入口，并在正文和 `manifest.json` 同时登记发布者、发布日期（可获得时）、访问日期、复核角色与下次复核日期。
7. 导入程序只接收当前目录清单内的文件。上级 `sample_docs/` 中的旧占位示例已退役，不得作为事实知识导入。
8. `manifest.json` 必须为每条来源声明 `source_tier`；助手存在多个来源时优先使用 `primary_authority`，并明确区分官方原文与厂商研判。
9. 清单明确列出的官方 PDF 或 HTML 原始文件可归档到项目，由 RAG 直接解析本地副本；来源 URL 仅用于溯源、更新检查与重新获取。动态目录页必须标明快照日期，不能替代具体法规正文。

## 更新节奏

- 在野利用漏洞：每天检查 CISA KEV 与厂商紧急公告；高危且与资产相关时立即新增条目。
- ATT&CK：每次 MITRE 版本更新后 10 个工作日内核对战术、技术和检测映射。
- 中国监管政策：每月检查中央网信办、国家标准和行业主管部门；重大法规生效前完成控制映射。
- 深信服官方研究：每半月检查千里目、PSIRT 与规则库；新报告先核对声明、数据时间范围和外部引用，再形成项目摘要。
- 每条资料采用 `YYYY-MM` 版本；失效内容标记为 archived，而不是直接覆盖。
