# 安全设备日志与检测运营基础（2026-09）

> 版本：2026.09.0｜最后核验：2026-09-09｜下次复核不晚于：2026-10-02｜复核角色：安全运营知识库管理员｜资料属性：内部安全知识库。本文描述传统防火墙、IDS/IPS、终端检测、SIEM 与 XDR 的职责边界和日志关联方法。

## 1. 设备与平台职责

- 防火墙根据地址、端口、协议、会话状态和策略控制通信；“允许”只表示策略放行，不表示流量安全。
- IDS 观察并产生检测告警，IPS 可在部署模式和策略允许时阻断；规则命中仍需结合上下文验证。
- NDR/NTA 从网络元数据、协议和流量行为发现异常，通常看不到主机内部因果链。
- EDR/XDR 侧重端点行为、身份、网络和其他遥测的关联。XDR 是关联与响应平台，不是所有上游探针的替代品。
- SIEM 负责集中采集、标准化、查询、关联和留存；日志被接入 SIEM 不等于已经形成可信事件。

NIST 对网络入侵检测与防御技术的基础说明：https://csrc.nist.gov/pubs/sp/800/94/final

## 2. 标准化前后的证据

原始日志必须保留，标准化事件至少包含事件时间、接收时间、设备与产品、事件类型、严重度、规则标识、主体、客体、网络五元组、动作、结果和原始证据引用。字段缺失应保持为空或 UNKNOWN，不能用默认值伪装成传感器事实。

不同设备的 severity、action 和 outcome 含义并不一致。例如 `blocked` 可能表示会话建立前拒绝，也可能只是后续报文被丢弃；`success` 可能仅表示请求被服务接收。映射规则需要版本、测试样本和回滚记录。

## 3. 日志质量

日志源应监控覆盖率、延迟、时钟偏差、重复率、解析失败率、字段完整率和静默中断。调查时间线同时保存 `occurred_at` 与 `received_at`，避免把网络延迟或批量转发时间当成攻击顺序。

敏感字段应按用途收集；认证令牌、密码、会话标识和个人信息不得原样进入普通检索索引。访问、导出、删除与保留期都应审计。

NIST 日志管理基础指南：https://csrc.nist.gov/pubs/sp/800/92/final

OWASP 应用安全日志指南：https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html

## 4. 从告警到案件

告警是某条检测逻辑的输出，案件是围绕共同实体和时间窗口组织的调查单元。合并告警时可使用端点、账号、IP、域名、进程、文件、规则家族和时间邻近性，但必须保留每条原始告警，防止关联错误掩盖差异。

推荐流程：采集原始日志 → 解析与标准化 → 数据质量校验 → 规则或模型检测 → 告警去重和关联 → 证据补充 → 风险判断 → 响应计划 → 策略授权 → 工具执行 → 状态验证 → 案件关闭和规则反馈。

## 5. 检测规则质量

每条规则记录目的、数据源、必要字段、逻辑版本、预期正常行为、严重度、适用资产、验证样本和停用条件。评价规则不能只看告警数，应同时看真阳性、误报、漏报抽样、平均调查时间、数据覆盖和规则陈旧度。

阈值不应直接复制到所有资产；域控制器、互联网边界、开发测试机和批处理服务器的基线不同。自动化处置必须基于案件确认事实和允许的目标范围，而不是仅依据一个规则编号。
